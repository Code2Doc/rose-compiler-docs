Annotates an AST subtree with execution counts from an external instruction file.

Annotates each SgAsmInstruction with a number indicating how often this instruction was executed

the needed pin tool which generates this file can be found in util/pin/my_itrace.cpp

Parameters
projthe (binary) SgProject to annotate
instfilepath of file with pairs of address - execCount format "addressInHex \t count \n" can for example be generated by intel-pin

This function reads an instruction trace file containing hexadecimal addresses and corresponding execution counts. It then traverses the provided SgNode subtree to find all nodes of type V_SgAsmInstruction. For each identified assembly instruction, the function looks up its address in the parsed map and attaches a new MetricAttribute named "Execution Count" to the node.

Parameters
projA pointer to the root SgNode of the subtree to be annotated.
instfileA string representing the path to the input file. The file must follow the format "addrInHex \t execCount\n".
Warning
The function assumes that the input file is formatted correctly with hexadecimal addresses followed by decimal execution counts. If the file cannot be opened, an error is printed to stderr and the function returns without modifying the AST.
The function uses an assertion to ensure that nodes identified by NodeQuery are valid SgAsmStatement objects.
Precondition
The file specified by instfile must exist and be readable.
The proj pointer must be a valid, non-null pointer to an SgNode.
Postcondition
If successful, all SgAsmStatement nodes within the proj subtree will have an additional "Execution Count" attribute containing the value parsed from the input file.
Note
The function creates a file named "control.out" during execution, though its primary use in this snippet is for output stream initialization.
The parsing logic relies on the std::hex and std::dec manipulators to switch between hexadecimal and decimal reading modes.

Executes the project binary and annotates the AST with instruction execution counts using ptrace.

Annotates each SgAsmInstruction with a number indicating how often this instruction was executed

Parameters
projthe (binary) SgProject to annotate
argsarray with parameters for the process to trace (only parameter i.e. args[0] is NOT the exec name

This function performs dynamic analysis by running the executable associated with the provided project node. It utilizes the PTracer mechanism (enabled via the ifdef ROSEQT_EXPERIMENTAL directive) to intercept execution. The process involves identifying the executable path from the project's file information, loading the process with the provided arguments, and iterating through all assembly instruction nodes (V_SgAsmInstruction) in the AST to set breakpoints. After the execution completes, the function retrieves breakpoint information (hit counts) and attaches this data to the corresponding AST nodes as a new "Execution Count" attribute.

Parameters
projA pointer to the SgNode representing the project to be annotated. The node must contain valid file information pointing to an executable.
argsA vector of strings containing the command-line arguments to be passed to the executable during the tracing process.
Precondition
The ifdef ROSEQT_EXPERIMENTAL flag must be defined during compilation for the tracing logic to execute.
The proj node must have valid file information (Sg_File_Info) that points to a valid executable file.
Postcondition
The AST nodes corresponding to assembly instructions will have an additional "Execution Count" attribute containing the number of times that instruction was hit during execution, provided the tracing was successful.
Note
If ROSEQT_EXPERIMENTAL is not defined, the function will print an error message to stderr indicating that the experimental feature is unavailable.
This function relies on the PTracer class to handle the low-level ptrace mechanisms and breakpoint management.

This function performs dynamic analysis by running the executable associated with the provided project node and using the PTracer mechanism to monitor instruction execution. It identifies all assembly instruction nodes within the project's AST, sets breakpoints at each instruction using ptrace, and subsequently updates the AST nodes with a new "Execution Count" attribute based on the hit count recorded during execution.

The implementation relies on the ifdef ROSEQT_EXPERIMENTAL macro being defined. If the macro is not defined, the function will output an error message to stderr indicating that the experimental PTracer feature is unavailable.
