int double_cmp ( const void * a,
const void * b )

Compares two double-precision floating-point numbers.

This function provides a comparison interface compatible with standard C library functions like qsort. It casts the provided void pointers to double pointers and dereferences them to compare the underlying double values. The comparison logic returns 0 if the values are equal, -1 if the first value is less than the second, and 1 if the first value is greater than the second.

Parameters
aA pointer to the first double value to be compared.
bA pointer to the second double value to be compared.
Returns
An integer indicating the relationship between the two values: 0 if aa == bb, -1 if aa < bb, and 1 if aa > bb.
Precondition
The pointers a and b must not be null and must point to valid, memory-aligned double-precision floating-point numbers.
Postcondition
The state of the memory pointed to by a and b remains unchanged.
Note
This function performs a direct equality check using the == operator, which may be sensitive to precision issues inherent in floating-point arithmetic.

Compares two 64-bit integers for sorting or ordering purposes.

This function implements a standard comparison logic suitable for use with functions like qsort. It casts the provided void pointers to pointers of type int64_t and compares the underlying values. The comparison returns -1 if the first value is less than the second, 1 if it is greater, and 0 if they are equal.

Parameters
aA pointer to the first value, which must be a pointer to an int64_t.
bA pointer to the second value, which must be a pointer to an int64_t.
Returns
An integer indicating the relationship between the two values:
  • A negative value (specifically -1) if aa < bb.
  • Zero (0) if aa == bb.
  • A positive value (specifically 1) if aa > bb.
Precondition
The pointers a and b must not be null and must point to valid, dereferenceable memory containing an int64_t value.
Postcondition
The state of the memory pointed to by a and b remains unchanged.
Note
This function assumes that the memory pointed to by the void pointers is correctly aligned for int64_t access.

◆ node_destroy()

void node_destroy ( node * n)

Recursively deallocates a node and its entire subtree.

This function performs a post-order traversal of a binary tree structure to ensure that all child nodes and the associated data within each node are properly freed. It first checks if the provided pointer is not null, then frees the data member of the current node, followed by recursive calls to destroy the left and right children if they exist. Finally, the memory for the current node itself is released.

Parameters
nA pointer to the root node of the tree (or subtree) to be destroyed. If the pointer is NULL, the function performs no action.
Precondition
The pointer n must point to a validly allocated node structure, or be NULL.
Postcondition
The memory associated with the node n, its children, and the data pointed to by n->data is released. The pointer n becomes dangling.
Warning
Calling this function on a pointer that has already been freed will result in undefined behavior.
Note
This function relies on the xfree function for memory deallocation.

◆ node_insert()

void node_insert ( node ** n,
cmp_func cmp,
void * e )

Inserts a new element into a binary search tree or updates an existing one.

This function performs a recursive insertion into a binary tree structure. If the tree is empty, a new node is allocated and initialized. If the tree is not empty, the function uses a provided comparison function to determine the placement of the new element. If the element already exists (comparison returns 0), the count of the existing node is incremented and the new element's memory is freed. If the element is "greater" than the current node, it is inserted into the left subtree; otherwise, it is inserted into the right subtree.

Parameters
nA pointer to a pointer of type node, representing the current node being evaluated. This allows the function to modify the parent's child pointer.
cmpA function pointer used to compare the data within the current node with the new element. The function should return 0 if equal, a positive value if the new element is "less" (to go left), and a negative value if the new element is "greater" (to go right).
eA pointer to the data/element to be inserted into the tree.
Precondition
The pointer n must be a valid address of a node*.
The cmp function must be a valid, non-null function pointer.
The memory pointed to by e must be valid and accessible.
Postcondition
If the element e already exists in the tree, the count of the existing node is incremented and the memory for e is released via xfree.
If the element e does not exist, a new node is added to the tree, and the tree structure is updated.
Warning
If the comparison function returns 0, the memory pointed to by e is automatically freed using xfree. The caller must ensure that e is managed correctly to avoid double-free or memory leaks.
This function uses recursion; extremely deep trees may lead to stack overflow.

Performs an in-order traversal of a binary tree node and applies a callback function.

This function implements a recursive in-order traversal algorithm (Left-Root-Right) on a binary tree structure. For every valid node encountered, the provided callback function iter is executed using the node's data, count, and a user-defined pointer. The traversal continues down the left child before processing the current node, and then proceeds to the right child.

Parameters
nA pointer to the root node of the tree (or subtree) to be traversed. If the pointer is null, the function returns immediately.
iterA function pointer or iterator-like object that defines the action to be performed on each node. It accepts the node's data, the node's count, and a context pointer.
pA generic pointer to user-defined data or context that is passed directly to the iter callback function.
Precondition
The iter function pointer must be valid and non-null to avoid undefined behavior.
Postcondition
All nodes in the subtree rooted at n will have been visited by the iter function.
Note
The traversal is recursive; therefore, extremely deep trees may lead to stack overflow.

◆ RegisterExtensionFunctions()

int RegisterExtensionFunctions ( sqlite3 * db)

Registers a collection of mathematical, string, and aggregate extension functions into a SQLite database connection.

This function iterates through two internal static arrays, aFuncs and aAggs, which contain definitions for scalar and aggregate functions respectively. It uses the sqlite3_create_function API to register each function into the provided SQLite database connection. The registered functions include mathematical operations (e.g., sin, cos, log, sqrt), string manipulation utilities (e.g., replicate, leftstr, replace), and statistical aggregate functions (e.g., stdev, variance, median).

The registration process handles different argument types and text representations (UTF-8). Some functions are configured to receive the database pointer as user-defined data.

Parameters
dbA pointer to an open sqlite3 database connection where the functions will be registered.
Returns
Returns 0 upon successful completion of the registration loop.
Precondition
The db parameter must be a valid, non-null pointer to an initialized sqlite3 database connection.
Postcondition
The specified extension functions are available for use in SQL queries executed on the db connection.
Note
The implementation currently lacks error checking for the sqlite3_create_function calls.
Certain string functions like ltrim, rtrim, and trim are only registered if the ifndef HAVE_TRIM macro is active.

This function serves as a wrapper around the standard C library function calloc. It allocates the requested amount of memory for an array of nmemb elements, each of size bytes, and ensures that the allocated memory is zero-initialized. The parameter s is currently unused in the implementation but is part of the signature.

Parameters
nmembThe number of elements to be allocated.
sizeThe size in bytes of each element to be allocated.
sA character pointer, which is not utilized within the function body.
Precondition
The product of nmemb and size must not exceed the maximum value of size_t.
Postcondition
The returned pointer points to a block of memory of size (nmemb * size) that has been zero-initialized, or NULL if the allocation fails.
Note
This function relies on the underlying implementation of the standard calloc function.

◆ xfree()

void xfree ( void * p)

Deallocates the memory previously allocated for the pointer p.

This function serves as a wrapper around the standard C library function free(). It is used to release the memory block pointed to by p, which must have been previously allocated via a compatible allocation function such as malloc, calloc, or realloc.

Parameters
pA pointer to the memory block to be freed. If p is a null pointer, no action is performed.
Precondition
The pointer p must have been returned by a previous call to a memory allocation function (e.g., malloc, calloc, realloc).
Postcondition
The memory block pointed to by p is no longer valid and should not be accessed.
Note
This function is a thin wrapper and behaves identically to the standard free() function regarding memory management and side effects.
