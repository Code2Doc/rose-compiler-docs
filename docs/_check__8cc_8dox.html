bool checkType ( const SgStatement * s)

Verifies if a given statement belongs to a predefined set of supported statement types.

This function inspects the variant type of the provided SgStatement pointer. It checks whether the statement's variant matches any of the specific allowed types, such as arithmetic if statements, basic blocks, loops (for, while, do-while), declarations, and various control flow statements (break, continue, return, goto, etc.).

Parameters
sA pointer to the SgStatement to be checked.
Returns
True if the statement's variant is within the supported list of types; false otherwise, or if the input pointer s is null.
Precondition
The pointer s should ideally point to a valid SgStatement object.
Postcondition
The function does not modify the state of the input SgStatement.
Note
If the input pointer s is null, the function returns false.
The list of supported variants is hardcoded within a switch statement.

bool doesCall__builtin_va_start ( const SgStatement * s)

Checks if a given statement contains a call to the __builtin_va_start intrinsic.

This function performs a subtree query on the provided SgStatement to identify any function reference expressions that point to the specific built-in function named "__builtin_va_start". It iterates through all identified function references within the statement's scope and compares their symbol names to the target string.

Parameters
sA pointer to the SgStatement to be inspected.
Returns
True if the statement contains a call to __builtin_va_start, false otherwise.
Precondition
The pointer s must be a valid pointer to an SgStatement object.
Postcondition
The state of the SgStatement s remains unchanged (read-only inspection).
Note
This function uses NodeQuery::querySubTree with the V_SgFunctionRefExp criteria to locate potential calls.
The function performs a const_cast on the input pointer to facilitate the query, but does not modify the underlying AST structure.

bool doesRefHiddenTypes ( const SgStatement * s)

Checks if any variable references or declarations within a statement involve hidden types.

This function traverses the subtree of a given SgStatement to identify if any SgVarRefExp (variable references) or SgVariableDeclaration (variable declarations) utilize a type that is classified as a hidden type via the isHiddenType function. The implementation performs two separate queries using NodeQuery::querySubTree: first, it iterates through all variable references to check their associated types, and second, it iterates through all variable declarations to check the types of all initialized names within those declarations.

Parameters
sA pointer to the SgStatement to be inspected.
Returns
True if at least one variable reference or declaration within the statement contains a type identified as hidden; false otherwise.
Precondition
The pointer s must be a valid pointer to an SgStatement or nullptr. If s is nullptr, the behavior of NodeQuery::querySubTree depends on the implementation of the query engine.
Postcondition
The state of the SgStatement s remains unchanged as the function performs read-only inspections, although const_cast is used internally for the query.
Note
This function relies on the isHiddenType function to determine the hidden status of a type.

Parameters

Returns

Precondition

bool isForInitOrTest ( const SgStatement * s)

Determines if a given statement is part of a for-loop's initialization or test condition.

This function checks whether the provided statement s is an initialization statement or a test condition within a for-loop structure. The check is performed by examining the statement itself, its parent node, and the components of the for-loop if the parent is identified as a for-loop. It specifically looks for matches within the list of initialization statements and the test expression of the loop.

Parameters
sA pointer to the SgStatement to be inspected.
Returns
True if the statement is an initialization statement or a test condition of a for-loop; false otherwise. Returns false if the input pointer s is null.
Precondition
The pointer s should ideally point to a valid SgStatement object, though the function handles null pointers gracefully.
Postcondition
The state of the input statement s remains unchanged.
Note
This implementation relies on the parent-child relationship within the SgNode hierarchy. It specifically checks isSgForInitStatement on the parent node and iterates through the list of statements returned by loop->get_init_stmt().

bool isHiddenType ( const SgType * type)

Determines whether a given type is a hidden type.

A type is considered "hidden" if its base type is a named type whose declaration exists within a scope that is not global, a class definition, or a namespace definition. The function traverses the scope hierarchy of the type's declaration upwards to the global scope to check for such nesting.

Parameters
typeA pointer to the SgType to be checked.
Returns
True if the type is identified as a hidden type; false otherwise. Returns false if the input type is null or if the type is not a named type with a detectable declaration scope.
Precondition
The input pointer type should be a valid pointer to an SgType object, though the function handles null pointers gracefully.
Postcondition
The state of the input type remains unchanged.
Note
The function relies on the existence of helper functions such as isSgNamedType, isSgGlobal, isSgClassDefinition, and isSgNamespaceDefinitionStatement.
