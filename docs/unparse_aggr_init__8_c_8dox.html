bool containsIncludeDirective ( SgLocatedNode * locatedNode)

Checks if a given located node contains an include preprocessor directive.

This function iterates through the attached preprocessing information associated with the provided SgLocatedNode. It examines each preprocessing directive to determine if any directive of type PreprocessingInfo::CpreprocessorIncludeDeclaration resides within the source code range defined by the start and end of the node's construct. The function also verifies that the preprocessing information belongs to the same file as the node's construct.

Parameters
locatedNodeA pointer to the SgLocatedNode to be inspected for include directives.
Returns
True if an include directive is found within the bounds of the node's construct, false otherwise.
Precondition
locatedNode must not be NULL.
Postcondition
The state of the locatedNode is not modified.
Note
The function relies on the node's start and end constructs being valid and comparable to the file information stored in the attached preprocessing info.

void removeIncludeDirective ( SgLocatedNode * locatedNode)

Removes C preprocessor include directives attached to a specific node.

This function iterates through the attached preprocessing information associated with a given SgLocatedNode. It identifies any attached directives that are of type PreprocessingInfo::CpreprocessorIncludeDeclaration and are located within the spatial boundaries of the node (between the start and end of the construct). Once identified, these specific include directives are removed from the node's attached preprocessing information list.

Parameters
locatedNodeA pointer to the SgLocatedNode whose attached preprocessing information is to be inspected and modified.
Precondition
locatedNode should not be NULL to avoid dereferencing errors when accessing attached preprocessing info.
Postcondition
The attached preprocessing information of locatedNode will no longer contain any directives identified as C preprocessor include declarations that were within the node's range.
Note
The function uses include and define logic implicitly by interacting with the PreprocessingInfo type. It relies on the node's start and end constructs to validate the file location of the directive.

bool sharesSameStatement ( SgExpression * expression,

Determines if a type definition is embedded within the same statement as an expression.

This function performs structural analysis to decide whether a compound literal should be unparsed using its full type definition or merely its type name. It inspects the underlying declaration of the provided type to check if the declaration is part of a larger, embedded statement (such as a variable or typedef declaration) or if it stands as an autonomous declaration.

Parameters
expressionA pointer to the SgExpression associated with the type.
expressionTypeA pointer to the SgType representing the type of the expression.
Returns
True if the type declaration is embedded within another statement (e.g., part of a variable or typedef declaration) and is not an autonomous declaration; false otherwise.
Precondition
expressionType must not be NULL if the function is to perform type-specific analysis.
If expressionType is a named type, its declaration must not be NULL, as the function performs an ASSERT_not_null on the result of get_declaration().
Postcondition
The return value indicates whether the type's definition is structurally linked to a parent statement, which guides the unparsing logic for compound literals.
Note
This implementation specifically handles cases where a class declaration might be part of a variable or typedef declaration to ensure correct unparsing for complex C/C++ source structures.

bool uses_cxx11_initialization ( SgNode * n)

Determines if a given AST node uses C++11 initialization features for structs.

This function inspects the structure of an initialization sequence to identify patterns characteristic of C++11 brace-initialization. It performs two primary checks:

  1. It traverses the initializer chain (up to three levels) to see if it follows a specific pattern involving a class type, an array type, and another class type, which may require specific class specifiers.
  2. It checks if the node is part of a template instantiation where the initializer argument might require the use of a class specifier to trigger the instantiation.

The implementation uses an internal AstSimpleProcessing subclass, InitializerTraversal, to collect SgInitializer nodes by traversing the AST subtree in preorder.

Parameters
nThe AST node to be inspected for C++11 initialization patterns.
Returns
true if the node is identified as using C++11 specific initialization features that require class specifiers; false otherwise.
Precondition
n must not be NULL.
Postcondition
The function does not modify the state of the input node n, but may traverse its parent and children.
Note
The function relies on several ROSE-specific type-checking functions such as isSgAggregateInitializer, isSgClassType, and isSgArrayType.
The logic includes checks for template instantiations via SageInterface::isTemplateInstantiationNode.
