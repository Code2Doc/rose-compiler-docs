bool DUVariableAnalysisExt::calcUseDefs ( SgNode * node,
bool getDef,
bool getIndirect )

Determines if a specific variable reference is being defined or used, either directly or indirectly.

This function performs an upward traversal in the Abstract Syntax Tree (AST) starting from a given SgNode (expected to be a variable reference expression). It analyzes the parent nodes to identify if the variable is subject to a definition (assignment, increment/decrement, etc.) or a use (reading the value, member access, etc.). The function distinguishes between direct access and indirect access (e.g., through pointers or array indexing).

The algorithm iterates through the ancestors of the node until it reaches a statement boundary or a node that terminates the analysis. It handles various expression types such as assignment operators, pointer dereferencing, address-of operators, and function call arguments.

Parameters
nodeThe starting SgNode, which must be an instance of SgVarRefExp.
getDefA boolean flag indicating whether the function should check for a definition (true) or a use (false).
getIndirectA boolean flag indicating whether to check for indirect access (true) or direct access (false).
Returns
True if the specified condition (definition or use, direct or indirect) is met; otherwise, false. Returns false if the input node is not an SgVarRefExp.
Precondition
The input node must be a valid pointer and must represent an SgVarRefExp.
Postcondition
The function does not modify the state of the AST nodes, but may print error messages to cerr if the node type is invalid or if an address-of operator is used on a variable.
Note
The function relies on several helper functions such as isSgVarRefExp, isSgStatement, isAssignmentExpr, isSgBinaryOp, isSgAssignOp, isSgDotExp, isSgArrowExp, isSgPntrArrRefExp, isSgPlusPlusOp, isSgMinusMinusOp, isSgExprListExp, isSgFunctionCallExp, isSgAddressOfOp, isPointerType, isComposedType, isSgPointerDerefExp, and isSgAddressOfOp.
Warning
If the input node is not an SgVarRefExp, the function will print an error to cerr and return false.
Using the %& (address-of) operator on a variable will trigger an error message to cerr and result in both direct and indirect use/def flags being set to true.

Determines if a variable reference is being used with an address-of operator within a function call context.

This function performs an upward traversal from a given variable reference node (node) through its ancestors in the Abstract Syntax Tree (AST) until it reaches the specified function call node (call). The algorithm checks various expression types to determine if the variable is being passed by reference via an address-of operator or if it is being transformed by other operators (like assignment, member access, or array dereferencing) that would negate the "address-of" property.

Parameters
nodeA pointer to the SgVarRefExp node representing the variable reference being inspected.
callA pointer to the SgFunctionCallExp node that serves as the upper bound for the traversal.
Returns
True if an address-of operator is encountered during the traversal up to the call node. Returns false if the traversal reaches the call node without finding an address-of operator, or if the variable is intercepted by an assignment, member access, or array dereference.
Precondition
The node and call pointers must be valid and not null. The node should be a descendant of call within the AST.
Postcondition
The function does not modify the state of the AST nodes.
Warning
If the traversal reaches an SgStatement node before reaching the call node, the function will print an error to cerr and trigger a ROSE_ABORT().
Note
The logic specifically handles cases for:
  • Assignment expressions where the current node is the right-hand side.
  • Member access via dot (.) or arrow (->) operators.
  • Array/pointer dereferencing via [].
  • Expression lists.
  • The address-of operator (&).

SgNode * DUVariableAnalysisExt::getNextParentInterstingNode ( SgNode * node)

Traverses up the AST hierarchy to find the next node considered "interesting".

This function performs an upward traversal from a given starting node through its parent pointers. The traversal continues until it encounters a node that meets specific criteria for being "interesting" for program slicing or control flow analysis, or until it reaches the root of the AST (NULL).

The algorithm skips nodes that are simple variable references (SgVarRefExp) and stops at nodes that represent significant structural elements such as function calls, function declarations, function definitions, or nodes identified by the IsImportantForSliceSgFilter predicate. It also identifies boundaries related to function arguments and parameter lists.

Parameters
nodeThe starting SgNode from which the upward traversal begins.
Returns
A pointer to the first "interesting" ancestor node found, or NULL if the traversal reaches the top of the tree without finding an interesting node.
Precondition
node should be a valid pointer to an SgNode or NULL.
Postcondition
The returned node is either NULL or an ancestor of the input node that satisfies one of the termination criteria.
Note
The term "interesting" is context-dependent, referring to nodes that are relevant for CFG construction or slicing operations.
