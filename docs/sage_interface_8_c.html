Adds a new argument to a function parameter list and manages associated symbol metadata.

This function inserts a new initialized name into an existing parameter list, either at the beginning or the end. It handles the necessary linkage between the parameter, its declaration, and the underlying scope. Specifically, it ensures the parent of the initName is set to the parameter list, updates the declaration pointer if the parameter list belongs to an SgFunctionDeclaration, and manages the scope and symbol table insertion for the variable symbol.

Parameters
paraListA pointer to the SgFunctionParameterList where the argument will be added.
initNameA pointer to the SgInitializedName representing the argument to be added.
isPrependA boolean flag indicating whether to prepend (true) or append (false) the argument to the parameter list.
Returns
A pointer to the SgVariableSymbol associated with the added argument if a scope is successfully established and the symbol is created/retrieved; otherwise, returns NULL if no scope is available.
Precondition
paraList must not be NULL.
initName must not be NULL.
Postcondition
The initName is added to paraList at the position specified by isPrepend.
If initName had no parent, its parent is set to paraList.
If the parent of paraList is an SgFunctionDeclaration, initName's declptr is updated.
If a scope is identified, the variable symbol is inserted into the scope's symbol table.
Note
This function performs internal assertions to verify the integrity of the parameter list and the initialized name.

◆ getGlobalScopeDeclaration()

SgDeclarationStatement * getGlobalScopeDeclaration ( SgDeclarationStatement * inputDeclaration)

Retrieves the declaration associated with the global scope for a given input declaration.

This function is used when a class or entity is defined within a nested scope (such as a namespace). When outlining references to such classes, it is necessary to declare the outer scope that contains the class, rather than the class declaration itself, to ensure the outer scope (which includes the class) is properly represented. The function traverses the scope hierarchy upwards from the input declaration's scope until it reaches the global scope, returning the declaration associated with that global scope.

Parameters
inputDeclarationA pointer to the SgDeclarationStatement whose global scope declaration needs to be identified.
Returns
A pointer to the SgDeclarationStatement that resides in the global scope and is associated with the hierarchy of the input declaration. If the input declaration is already in the global scope, it returns the input itself.
Precondition
inputDeclaration must not be NULL, and its associated scope must be valid and accessible via get_scope().
Postcondition
The returned pointer points to a valid SgDeclarationStatement that is part of the global scope hierarchy.
Note
The implementation relies on ROSE_ASSERT to ensure that the scope and associated declarations are not NULL during the upward traversal.

◆ getPermutationOrder()

std::vector< size_t > getPermutationOrder ( size_t n,
size_t lexicoOrder )

Retrieves the n-th lexicographical permutation of a sequence of size n.

A helper function to return a permutation order for n elements based on a lexicographical order number. See also, Combinatorics::permute(), which is faster but does not use strict lexicographic ordering.

This function computes the specific permutation of the sequence {0, 1, ..., n-1} that corresponds to the given lexicographical index (lexicoOrder). The algorithm uses a factorial-based approach to determine which element from the remaining available set should be placed at each position. It iteratively calculates the index of the element to be moved to the current position by dividing the lexicographical order by the factorial of the remaining elements, then shifts the elements in the vector to maintain the relative order of the remaining items.

Parameters
nThe number of elements in the permutation sequence.
lexicoOrderThe zero-based lexicographical index of the permutation to retrieve.
Returns
A vector of size_t containing the elements of the permutation in the specified lexicographical order.
Precondition
n must be such that (n-1)! can be computed and stored in a size_t, and lexicoOrder must be less than n!.
Postcondition
The returned vector contains a permutation of the integers from 0 to n-1.
Warning
If lexicoOrder is greater than or equal to n!, the function will print an error message and trigger a ROSE_ABORT().
Note
This implementation is specifically designed for strict lexicographical ordering. For cases where strict ordering is not required, Combinatorics::permute() may offer better performance.

bool isStructuredBlock ( SgStatement * s)

Check if an executable statement (possibly compound), is a structured block.

Determines if a given statement block is structured.

This function checks whether a statement block follows structured programming principles by verifying the absence of certain control flow disruptions. Specifically, it inspects the block for the presence of break statements that target loop-relevant nodes. The implementation utilizes SgNodeHelper::loopRelevantBreakStmtNodes to identify if any break statements exist within the scope of the provided statement.

Parameters
sA pointer to the SgStatement representing the block to be inspected.
Returns
True if the block is considered structured (contains no loop-relevant break statements), false otherwise.
Precondition
s must not be NULL.
Postcondition
The return value indicates the structural integrity of the block regarding break statements.
Note
The current implementation does not yet account for goto statements that jump to targets outside the block, nor does it explicitly check for longjmp() or throw() operations, though calls to exit() are permitted.

Moves declarations from a source block to a target block.

This function is utilized by the outliner to relocate statements and their associated declarations from one scope to another. It iterates through the declarations in the source block, moves each statement using moveOneStatement, and subsequently updates the symbol table and preprocessing information to maintain structural integrity.

Parameters

targetBlockA pointer to the target block where the declarations will be moved. Must not be null and must contain only declarations.
Precondition

sourceBlock->containsOnlyDeclarations() must be true.
targetBlock->containsOnlyDeclarations() must be true.
Postcondition
The sourceBlock will no longer contain the declarations that were moved.
The targetBlock will contain the declarations previously located in sourceBlock.
The symbol table information is updated to reflect the new location of the declarations.
Preprocessing information (such as endif) is moved from the source block to the target block.
Note
If sourceBlock and targetBlock are the same pointer, the function logs a warning to cerr and returns without performing any operations.
This function relies on moveOneStatement, moveSymbolTableBetweenBlocks, and SageInterface::moveUpPreprocessingInfo to complete the relocation process.

This function is primarily used by the outliner to relocate a sequence of statements from one scope to another. The process involves iterating through each statement in the source block and moving it to the target block using moveOneStatement. Additionally, the function handles the migration of initialized names (symbol table entries) and ensures that preprocessing information (such as ifdef, ifndef, endif, etc.) is correctly updated to maintain structural integrity between the source and target scopes.

Parameters
sourceBlockA pointer to the block containing the statements to be moved.
targetBlockA pointer to the destination block where statements will be relocated.
Precondition
sourceBlock and targetBlock must not be null.
Postcondition
The sourceBlock's statement list will be empty, and all its statements will have been moved to targetBlock. The symbol table and preprocessing information are updated accordingly.
Note
If sourceBlock and targetBlock are the same pointer, the function logs a warning to stderr and returns without performing any operations.
This function relies on moveOneStatement, moveSymbolTableBetweenBlocks, and SageInterface::moveUpPreprocessingInfo to complete the migration.

Populates a symbol table with variables from a provided list of initialized names.

This function iterates through a list of initialized names and inserts each variable into the provided symbol table as an SgVariableSymbol. If a mismatch is detected, a warning is printed to the standard output, provided that the SgProject verbose level is greater than 0.

Parameters

Precondition

Postcondition
The symbolTable will contain new SgVariableSymbol entries for every element in variableList.
Note
If the scope of a variable does not match the provided scope, a warning message is printed if SgProject::get_verbose() > 0. This may occur if the symbol table was initialized before scopes were properly set or if the variable is static.
