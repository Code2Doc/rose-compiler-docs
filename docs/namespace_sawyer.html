◆ checkBoost()

void Sawyer::checkBoost ( )

Validates the compatibility of the Boost library version with the C++ standard.

Check for valid boost version or abort.

This function performs a runtime check to ensure that the version of Boost being used is not version 1.54 when compiled with C++11 or later. This specific combination is known to cause infinite recursion in the boost::any move constructor, which eventually leads to a segmentation fault. Checking this at runtime allows other features of Boost 1.54 to remain usable while preventing the specific catastrophic failure associated with C++11 compatibility.

Warning
Using Boost 1.54 with C++11 (or higher) will trigger an assertion failure to prevent a segmentation fault caused by infinite recursion.
Precondition
The environment must have the BOOST_VERSION macro defined.
Postcondition
If the condition (BOOST_VERSION == 105400 and cplusplus >= 201103L) is met, the program will trigger an assertion failure via ASSERT_always_forbid2.

Generates a pseudo-random index within the range [0, n-1].

Thread-safe random number generator.

Generates uniformly distributed pseudo-random size_t values. The returned value is greater than zero and less than n, where n must be greater than zero except when seeding the sequence. To seed the sequence, call with n equal to zero and a non-zero seed; all other calls must supply a zero seed value. This function uses the fastest available method for returning random numbers in a multi-threaded environment. This function is thread-safe.

This function provides a fast way to obtain a random index from a range of size n. It utilizes a thread-local pseudo-random number generator to maintain efficiency across multiple calls. If a non-zero seed is provided, the generator is re-seeded with that value. The function uses a uniform distribution to ensure that each index in the range has an equal probability of being selected.

Parameters
nThe size of the range from which to pick an index.
seedThe seed value to initialize the generator. If 0, the existing thread-local generator state is preserved.
Returns
A pseudo-randomly selected index in the range [0, n-1]. Returns 0 if n is 0 and a seed is provided.
Warning
This implementation currently contains a memory leak regarding the thread-local SAWYER_PRN_GENERATOR instance, as thread-local storage for non-POD types cannot be automatically cleaned up by common compilers.
Precondition
The inputs must satisfy the condition: (n > 0 and seed == 0) OR (n == 0 and seed != 0).
Postcondition
The function returns an index that is valid within the bounds of the specified range.
Note
The function relies on a static thread-local variable for the generator, ensuring that the random sequence is continuous for a single thread unless explicitly re-seeded.

Retrieves the current system time as a high-resolution time point.

This function provides a platform-independent way to capture the current time by utilizing different underlying mechanisms based on the compilation environment. It uses ifdef logic to select between Boost.Chrono, Windows API, or POSIX implementations.

The implementation details are as follows:

  • If define SAWYER_HAVE_BOOST_CHRONO is active, it uses boost::chrono::high_resolution_clock::now().
  • If define BOOST_WINDOWS is active, it uses GetSystemTimeAsFileTime to retrieve the system time, converts the FILETIME structure into a 64-bit integer, scales it to microseconds, and returns the result.
  • Otherwise, it assumes a POSIX-compliant environment and uses gettimeofday to calculate the time in seconds with microsecond precision.
Returns
The current time represented as a Stopwatch::TimePoint. Returns 0.0 if the POSIX gettimeofday call fails.
Precondition
None.
Postcondition
The returned value represents a snapshot of the system clock at the moment of execution.
Note
The precision of the returned value depends on the underlying operating system and the availability of the Boost library.

Increments an optional value with overflow detection and carry handling.

This function performs a single-step increment operation on an optional value. It handles three primary logic branches:

  1. If the value is present and a carry-in is requested, it increments the value by 1. If the incremented value reaches or exceeds the maxValue, it wraps the value to the base value and signals an overflow via the boolean part of the pair.
  2. If the value is present but no carry-in is requested, the value remains unchanged.
  3. If the value is not present (empty), the function initializes the value to the provided base and signals a carry-in event.
Parameters
valueAn optional container holding the current value of type T.
maxValueThe upper threshold used to determine if an overflow/wrap-around occurs.
baseThe value to revert to if an overflow occurs or if the input value is empty.
carryInA boolean flag indicating whether an increment/carry operation should be applied.
Returns
A pair where the first element is the resulting value of type T, and the second element is a boolean indicating whether an overflow (wrap-around) or an initial carry event occurred.
Precondition
The type T must support comparison operators (>=, <), addition (+), and construction from an integer literal (T{1}).
Postcondition
The returned value will always be within a valid range relative to base and maxValue.
Note
This function is useful for implementing multi-precision arithmetic or counters that need to wrap around at specific boundaries.

Explicitly initialize the library.

This initializes any global objects provided by the library to users. This happens automatically for many API calls, but sometimes needs to be called explicitly. It can be called as often as desired; each call checks caller-callee consistency (version number and configuration), but only the first call does any initialization. The function always returns true.

This function performs a critical compatibility check between the version of the Sawyer header files used during compilation and the version of the linked library. It also verifies that the multi-threading configuration matches the expected state. If the version or threading flags are inconsistent, a std::runtime_error is thrown. Upon successful verification, it uses an Initializer object to perform the library setup, utilizing boost::call_once if SAWYER_MULTI_THREADED is defined, or a static flag for single-threaded environments. Finally, it registers a shutdown handler via atexit.

Processes all items in a work list using a specified number of worker threads.

Process work from a work list in parallel.

Processes each item in the work list by passing the item and the list of pending work to the provided functor. Up to maxWorkers work items are processed in parallel. The workList is responsible for holding the list of outstanding work items and hands them out one at a time according some priority. The WorkFifo is an example class that satisfies the WorkItems interface and hands out work items in the same order they were created. Since the functor is given a reference to the workList, wihch contains all pending work (work that hasn't started yet), the functor is able to modify the work list, such as adding additional work items.

This function iterates through a collection of work items and applies a provided functor to each. The implementation behavior depends on the SAWYER_MULTI_THREADED preprocessor directive.

If SAWYER_MULTI_THREADED is defined, the function implements a multi-threaded producer-consumer pattern. It manages a pool of detached threads up to a specified limit (maxWorkers). It uses a mutex and condition variable to synchronize worker threads, ensuring that new threads are spawned only when the maximum worker limit has not been reached and work is available. Each worker thread executes the functor on the next available item and decrements the active worker count upon completion, notifying the main loop.

If SAWYER_MULTI_THREADED is not defined, the function operates sequentially, processing each item in the work list one after another in the calling thread.

Parameters
workListA reference to a work list container. The container must implement isEmpty() and next() methods. The next() method is expected to retrieve the next item for processing.
maxWorkersThe maximum number of concurrent threads to allow. If this value is 0, the function defaults to the hardware concurrency reported by the system.
fThe functor or function object to be applied to each item in the work list. The functor must accept two arguments: the current item type and a reference to the work list itself.
Precondition
maxWorkers must be greater than 0 (if 0 is provided, it is internally reassigned to the hardware concurrency).
The workList must be in a valid state and its next() method must eventually lead to isEmpty() returning true to avoid infinite loops.
Postcondition
All items that were present in the workList at the start of the execution (and added during processing) will have been processed by the functor.
The workList will be empty (assuming the functor or the process removes items).
Note
This function uses detached threads in the multi-threaded implementation. The caller must ensure that the lifetime of the workList, the mutex, and the functor exceeds the lifetime of all spawned threads to avoid use-after-free errors.
The implementation uses a static Worker struct to wrap the functor call to facilitate compatibility with thread creation mechanisms that may not support modern lambda captures.

template<class DependencyGraph, class Functor>
void Sawyer::workInParallel ( const DependencyGraph & dependencies,
size_t nWorkers,
Functor functor )

Executes a given functor in parallel based on a dependency graph.

Performs work in parallel.

Creates up to the specified number of worker threads to run the tasks described in the dependencies graph (at least one thread, but not more than the number of items on which to work). The dependencies is a graph whose vertices represent individual tasks to be performed by worker threads, and whose edges represent dependencies between the task. An edge from task a to task b means that task b must complete before task a can begin. If the dependencies graph contains cycles then as much work as possible is performed and then a ContainsCycle exception is thrown.

The functor can be a class with operator(), a function pointer, or a lambda expression. If a class is used, it must be copyable and each worker thread will be given its own copy. The functor is invoked with two arguments: the ID number of the task being processed, and a reference to a copy of the task (vertex value) in the dependency graph. The ID number is the vertex ID number in the dependencies graph.

If a monitor is provided, it will be called once every period milliseconds with the following arguments: the dependencies graph, number of work items that have been completed, and the set of dependencies vertex IDs (std::set<size_t>) that are currently running.

The call does not return until all work has been completed.

This function orchestrates the parallel execution of tasks defined by a functor, respecting the constraints and execution order specified within a dependency graph. It utilizes the ThreadWorkers template class to manage a pool of worker threads, distributing the workload across the specified number of workers. The execution logic follows the topological order of the dependencies provided.

Parameters
dependenciesA reference to a DependencyGraph object containing the structural relationships and execution constraints for the tasks.
nWorkersThe number of worker threads to be utilized during the parallel execution process.
functorThe callable object or function representing the task to be executed by the workers.
Precondition
The dependencies graph must be well-formed and free of circular dependencies to ensure successful parallel execution.
Postcondition
The functor is executed for all applicable nodes in the dependency graph, and all threads are joined before the function returns.
Note
The actual threading mechanism and task scheduling are encapsulated within the ThreadWorkers implementation.
