1// DQ (5/4/2011): This is the redesign of the support for name qualification.
2// The steps are:
3// 1) All using directives put alias sysmbols into place into the scope
4// where they appear and for each symbol in the scope being used.
5// 1) Compute the hidden type tables
6// 2) Use the hidden type tables to determine which types need qualification.
7
8// * We will want to keep track of hidden variables too! But first handle types.
9// * When we refer to names it will be of either variables or types.
10
11// This is a part of a rewrite of the name qualification support in ROSE with the follwoing properties:
12// 1) It is exact (no over qualification).
13// 2) It handled visibility of names constructs
14// 3) It resolves ambiguity of named constructs.
15// 4) It resolves where type elaboration is required.
16// 5) The inputs are carried in the SgUnparse_Info object for uniform handling.
17// 6) The the values in the SgUnparse_Info object are copied from the AST references to the named
18// constructs to avoid where named constructs are referenced from multiple locations and the
19// name qulification might be different.
20//
21// 7) What about base class qualification? I might have forgotten this one! No this is handled using standard rules (above).
