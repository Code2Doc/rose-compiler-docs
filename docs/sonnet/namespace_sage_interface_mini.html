string SageInterface::get_name ( const SgC_PreprocessorDirectiveStatement * directive)

Retrieves the class name string associated with a given C preprocessor directive statement node.

This function returns a human-readable name for a given SgC_PreprocessorDirectiveStatement node in the ROSE compiler AST (Abstract Syntax Tree). It uses the node's built-in class_name() method to obtain the name, and validates the directive type via a switch statement over all known preprocessor directive variant types. The function handles a broad set of preprocessor directive variants including include directives, define/undef directives, conditional compilation directives (ifdef, ifndef, if, else, elseif, dead-if), line directives, warning and error directives, empty directives, C linkage start/end statements, and Fortran include lines.

If the directive's variant type does not match any of the explicitly handled cases, a warning message is printed to standard output and the program is aborted via ROSE_ABORT(). This behavior is intentional to catch unhandled directive types during development and testing.

The function initializes the return value to "undefined_name" as a safety default before any processing occurs. In all currently handled cases, the return value is set to the result of directive->class_name().

Parameters
directiveA pointer to a constant SgC_PreprocessorDirectiveStatement node whose name is to be retrieved. This pointer must not be NULL.
Returns
A string containing the class name of the given preprocessor directive node as returned by its class_name() method. Returns "undefined_name" only if an unexpected code path is somehow reached prior to the switch statement, though in practice the function will abort on unrecognized variants before returning.
Warning
If the directive's variant type is not one of the explicitly handled cases in the switch statement, the function prints a warning message to standard output and calls ROSE_ABORT(), terminating the program. This means the function does not return gracefully for unknown directive types.
Precondition
The parameter directive must not be NULL. A failed ROSE_ASSERT will be triggered if a NULL pointer is passed.
The directive must be a valid, fully constructed SgC_PreprocessorDirectiveStatement node within the ROSE AST with a recognized variantT() value.
Postcondition
The returned string is equal to the result of directive->class_name() for all currently supported directive variant types.
The state of the directive node and the surrounding AST is not modified by this function.
Note
The switch statement in the implementation is noted by the original author as potentially unnecessary ("I don't think we need this code now!"), since all handled cases simply call directive->class_name() identically. The structure is preserved for completeness and to explicitly enumerate supported variants.
This function is part of the SageInterface utility layer in the ROSE compiler infrastructure, which provides helper functions for traversing and querying the ROSE AST.
The V_SgFortranIncludeLine variant is handled here even though it is not strictly a C preprocessor directive, reflecting the broader scope of the SgC_PreprocessorDirectiveStatement hierarchy in ROSE.

string SageInterface::get_name ( const SgDeclarationStatement * declaration)

Retrieves a human-readable name string for a given declaration statement node in the ROSE AST.

This function inspects the concrete type of the provided SgDeclarationStatement node using its variant discriminator (variantT()) and dispatches to the appropriate name-extraction logic for each supported declaration kind. The function handles a broad range of declaration types spanning C, C++, Fortran, Java, Jovial, and Ada language constructs supported by the ROSE compiler infrastructure.

For named declarations such as functions, classes, enumerations, namespaces, typedefs, and template variants, the function directly retrieves the symbolic name stored in the AST node via get_name().str() or equivalent accessor methods.

For declarations that do not carry a natural symbolic name (e.g., pragma declarations, variable definitions, Fortran statements, assembly statements, Java import statements, and various Ada clauses), the function constructs a descriptive synthetic name by combining a fixed prefix string with the memory address of the node converted to a string via StringUtility::numberToString(). This ensures uniqueness of the returned name even for anonymous or unnamed constructs.

Special cases include:

  • C preprocessor directive statements, which are handled by delegating to the overloaded get_name(const SgC_PreprocessorDirectiveStatement*) variant before the switch dispatch.
  • SgFunctionParameterList nodes, whose name is derived from the enclosing function or scope declaration with a "_parameter_list_" suffix appended.
  • SgVariableDeclaration nodes, whose name is formed by concatenating the names of all declared variables with a "_variable_declaration_" prefix.
  • SgAdaGenericDecl nodes, which delegate name resolution to the inner wrapped declaration.
  • SgAdaDiscriminatedTypeDecl nodes, which delegate to the discriminated sub-declaration when available, or return a placeholder string otherwise.
  • SgAdaParameterList nodes, whose name is built by accumulating the names of all parameter declarations using std::accumulate with a lambda.

If an unrecognized declaration variant is encountered, the function prints a warning to standard output and calls ROSE_ABORT() to terminate execution.

Parameters
declarationA pointer to a constant SgDeclarationStatement node whose name is to be retrieved. This pointer must not be NULL. The node must have its parent pointer set for certain declaration types (e.g., SgFunctionParameterList, SgCtorInitializerList, SgAsmStmt, and Fortran statement types) that require parent traversal to construct the name.
Returns
A std::string containing the name associated with the given declaration. For named declarations, this is the symbolic identifier as it appears in the source. For unnamed or synthetic declarations, this is a descriptive prefix combined with the node's memory address to ensure uniqueness. Returns "undefined_name" only if the name variable is not updated, which should not occur under normal operation since unhandled cases invoke ROSE_ABORT().
Warning
If the declaration pointer is NULL, the function will trigger a failed ROSE_ASSERT and abort execution. Callers must ensure the pointer is valid before calling this function.
If the declaration variant is not handled by any case in the switch statement, the function prints a diagnostic message and calls ROSE_ABORT(), terminating the program. This indicates an unimplemented case that must be added to support the new declaration type.
For SgFunctionParameterList nodes, the parent pointer must be set prior to calling this function. If the parent is neither an SgFunctionDeclaration nor an SgScopeStatement, ROSE_ABORT() is called.
Precondition
The parameter declaration must be a non-NULL pointer to a valid SgDeclarationStatement node within a properly constructed ROSE AST.
For declaration types that access their parent node (such as SgFunctionParameterList, SgCtorInitializerList, SgAsmStmt, and Fortran-specific statements), the parent pointer of the node must be set and non-NULL.
For SgVariableDeclaration nodes, the variable list must contain at least one initialized name entry; an empty variable list will trigger a failed ROSE_ASSERT.
Postcondition
The returned string is a non-empty string representing the name or a synthetic identifier for the given declaration node.
The AST and the declaration node are not modified by this function; all operations are read-only with respect to the AST structure.
Note
This function is part of the SageInterface utility layer in the ROSE compiler framework and is intended for use during AST traversal and analysis phases where human-readable identifiers for declaration nodes are needed.
The synthetic names generated for unnamed constructs incorporate the raw memory address of the node, which means they are unique within a single program run but are not stable across separate compilations or runs.
For Ada generic declarations (V_SgAdaGenericDecl), the function recursively calls itself on the inner wrapped declaration to obtain the name, rather than using a generic prefix.
Jovial-specific declaration types (V_SgJovialDefineDeclaration, V_SgJovialDirectiveStatement, V_SgJovialCompoolStatement) use the class_name() method combined with the node address to form the name, as noted in the source with a comment that get_name() for these types may need future correction.

string SageInterface::get_name ( const SgExpression * expr)

Returns a human-readable descriptive name string for a given ROSE AST expression node.

This function inspects the variant type of the provided SgExpression node and constructs a descriptive string name that reflects the kind and content of the expression. The function uses a switch statement on the expression's variant type (obtained via variantT()) to handle each recognized expression kind individually. For each supported expression type, a prefix string is assembled and, where applicable, recursively augmented with names derived from child sub-expressions by calling get_name() recursively.

The following expression types are explicitly handled:

  • SgVarRefExp: Produces a name of the form "var_ref_of_<symbol_name>".
  • SgLabelRefExp: Produces a name of the form "label_ref_of_<symbol_name>" (added to support Fortran alternate return parameters).
  • SgPntrArrRefExp: Produces a name of the form "array_ref_of_<lhs>_at_<rhs>", where lhs and rhs are recursively resolved.
  • SgFunctionCallExp: Produces a name of the form "function_call_<function_name>".
  • SgFunctionRefExp: Produces a name of the form "function_ref_<symbol_name>".
  • SgMemberFunctionRefExp: Produces a name of the form "member_function_ref_<symbol_name>".
  • SgIntVal: Produces a name of the form "integer_value_exp_<value>".
  • SgStringVal: Produces a name of the form "string_value_exp_<value>".
  • SgSubscriptExpression: Produces a name of the form "subscript_exp_<lowerBound>_<upperBound>_<stride>", with bounds and stride recursively resolved.
  • SgNullExpression: Produces the fixed name "null_expression".
  • SgExprListExp: Produces a name of the form "expr_list_exp_<name0><name1>...", concatenating all child expression names.
  • SgActualArgumentExpression: Produces a name incorporating the argument name and the sub-expression name (Fortran debugging support).
  • SgTemplateParameterVal: Produces a name of the form "template_parameter_value_expression_number_<position>".
  • SgDotExp: Produces a name of the form "_dot_exp_lhs_<lhs>_dot_exp_rhs_<rhs>".
  • SgLambdaExp: Produces the fixed name "lambda_expression_" (C++11 lambda support).
  • SgThisExp: Produces a name of the form "_this_exp_for_<class_name>".
  • Default (unrecognized types): Produces a name of the form "<class_name>_undef_name".

This function is primarily intended for debugging and diagnostic output within the ROSE compiler infrastructure.

Parameters
exprA pointer to a constant SgExpression node whose descriptive name is to be retrieved. The pointer must not be NULL, as the function dereferences it immediately to call variantT(). Child expression pointers accessed during recursive calls are also expected to be valid and non-NULL.
Returns
A std::string containing a human-readable name describing the expression. The returned string reflects the type and content of the expression node. If the expression type is not explicitly handled, a fallback string of the form "<class_name>_undef_name" is returned. The function never returns an empty string; at minimum it returns "undefined_name" if no case is matched (though in practice the default case overrides this).
Warning
Passing a NULL pointer for expr will result in undefined behavior, as the function does not perform a NULL check before calling expr->variantT(). The commented-out ROSE_ASSERT(expr != NULL) indicates this was previously enforced but is currently disabled.
For SgExprListExp nodes with a large number of child expressions, the resulting name string may become very long, as all child expression names are concatenated without any separator.
For SgActualArgumentExpression, the intermediate assignment to name using the argument_name prefix is overwritten before the function returns; only the sub-expression name portion is preserved in the final result.
Precondition
expr must be a valid, non-NULL pointer to an SgExpression node within a well-formed ROSE AST.
For expression types that access child symbols (e.g., SgVarRefExp, SgLabelRefExp, SgFunctionRefExp, SgMemberFunctionRefExp), the associated symbol pointers must be non-NULL, as they are asserted internally.
For SgThisExp, the associated class symbol (get_class_symbol()) must be non-NULL.
Postcondition
The returned string is a non-empty std::string describing the expression.
The input expression node and the AST are not modified by this function.
Note
This function is recursive. For deeply nested or complex expression trees, the recursion depth may be significant.
This function is intended for debugging purposes within the ROSE compiler infrastructure and is not designed for use in production code generation or transformation passes.
Support for several expression types (SgLabelRefExp, SgMemberFunctionRefExp, SgActualArgumentExpression, SgTemplateParameterVal, SgDotExp, SgLambdaExp, SgThisExp) was added incrementally over time to support Fortran, C++11, and template-related debugging scenarios.

string SageInterface::get_name ( const SgLocatedNodeSupport * node)

Returns a human-readable name string for a given SgLocatedNodeSupport IR node.

This function provides a general mechanism for retrieving a descriptive name from any SgLocatedNodeSupport node in the ROSE intermediate representation (IR). It is primarily intended as a debugging aid, allowing developers to quickly identify and distinguish IR nodes by their associated names or types.

The function operates by inspecting the runtime variant type of the provided node using a switch statement on the result of variantT(). Depending on the specific node type encountered, the function constructs a descriptive name string as follows:

  • SgRenamePair: Constructs a name of the form "rename_pair_<local_name>_from_<use_name>", combining the local name and the use name of the rename pair.
  • SgInitializedName: Constructs a name of the form "initialized_name_<variable_name>", using the declared variable's name.
  • SgLambdaCapture: Returns a name of the form "lambda_capture_" with no additional suffix (name retrieval for lambda captures is not yet fully implemented).
  • All other node types: Falls back to returning the class name of the node as provided by the class_name() member function.
Parameters
nodeA non-null pointer to a constant SgLocatedNodeSupport IR node for which the name is to be retrieved. This pointer must not be NULL; an assertion failure will occur if it is.
Returns
A std::string containing the descriptive name of the provided IR node. The format of the returned string depends on the specific node type, as described in the detailed description above. For unrecognized node types, the class name of the node is returned.
Warning
Passing a NULL pointer for the node parameter will trigger a failed assertion (ROSE_ASSERT), causing the program to abort. Always ensure the node pointer is valid before calling this function.
Precondition
The parameter node must not be NULL.
The node must be a valid, fully constructed SgLocatedNodeSupport object within the ROSE IR.
Postcondition
The returned string is non-empty for all supported node types, as either a constructed descriptive name or the class name is always returned.
The original node and its internal state are not modified by this function, as it operates on a const pointer.
Note
This function is primarily intended for debugging purposes and may not provide complete or fully qualified names for all node types.
Support for SgLambdaCapture was added in ROSE to handle C++11 lambda expression constructs. The name suffix for lambda captures is currently left empty pending further implementation.
Support for SgInterfaceBody is currently disabled via preprocessor guards and is not handled by this function.

string SageInterface::get_name ( const SgNode * node)

Returns a human-readable name string for a given ROSE IR (SgNode) node.

This function serves as the most general entry point for retrieving a descriptive name associated with any node in the ROSE Intermediate Representation (IR) tree. It is primarily intended for debugging purposes and provides a unified interface for obtaining names across the full hierarchy of IR node types.

The function works by performing a series of dynamic type checks (using ROSE's isSg* casting utilities) to determine the most specific category of the given node, then dispatching to the appropriate overloaded version of get_name():

  1. If the node is an SgLocatedNode, it is further examined:
    • If it is an SgStatement, get_name(SgStatement*) is called.
    • If it is an SgExpression, get_name(SgExpression*) is called.
    • If it is an SgLocatedNodeSupport, get_name(SgLocatedNodeSupport*) is called.
    • If it is an SgToken, get_name(SgToken*) is called.
    • Otherwise, an error is reported and execution is aborted.
  2. If the node is not an SgLocatedNode, it is further examined:
    • If it is an SgSupport, get_name(SgSupport*) is called.
    • If it is an SgSymbol, get_name(SgSymbol*) is called.
    • If it is an SgType, get_name(SgType*) is called.
    • Otherwise, the class name of the node is returned as a fallback.

If the node falls into an unrecognized SgLocatedNode subtype, the function prints a diagnostic message and calls ROSE_ABORT() to terminate execution.

Parameters
nodeA pointer to a constant SgNode whose name is to be retrieved. Must not be NULL.
Returns
A string containing the name associated with the given IR node. Returns "undefined_name" only if no matching category is found before the fallback to class_name(). In practice, a valid name or class name string is always returned for recognized node types.
Warning
If the node is an SgLocatedNode but does not match any of the known subtypes (SgStatement, SgExpression, SgLocatedNodeSupport, SgToken), the function will print an error message to standard output and call ROSE_ABORT(), terminating the program. This is a hard failure with no recovery mechanism.
Precondition
node must not be NULL. The function asserts this condition using ROSE_ASSERT and will abort if a NULL pointer is passed.
Postcondition
The returned string is a valid, non-empty string representing the name or class name of the given node. The input node and the IR tree are not modified by this function.
Note
This function is intended primarily as a debugging utility. It provides a convenient single point of dispatch for name retrieval across all IR node types in the ROSE framework. Future versions may be extended to handle additional expression types and other IR constructs. The fallback return value of the node's class_name() ensures that even unrecognized node types yield some meaningful output rather than a generic placeholder.

string SageInterface::get_name ( const SgScopeStatement * scope)

Retrieves a human-readable name string for a given SgScopeStatement node.

This function inspects the variant type of the provided SgScopeStatement node and dispatches to the appropriate name-retrieval logic based on the specific subclass of the scope. For named scopes such as class definitions, function definitions, namespace definitions, and Java label statements, the function delegates to corresponding overloads of get_name() applied to the associated declaration node, or directly extracts the label string. For unnamed or anonymous scopes such as basic blocks, loop bodies, conditional statements, and various language-specific constructs (Fortran, Ada, Matlab, Jovial, Java), the function returns a string representation of the pointer address of the scope node, produced via StringUtility::numberToString(). This provides a unique but non-symbolic identifier for scopes that do not carry a natural name.

The function uses a switch statement over the result of scope->variantT() to handle each recognized IR node type. If the variant type does not match any known case, an error message is printed and the program is aborted via ROSE_ABORT().

Supported named scope types include: SgTemplateClassDefinition, SgClassDefinition, SgTemplateInstantiationDefn, SgTemplateFunctionDefinition, SgFunctionDefinition, SgNamespaceDefinitionStatement, SgJavaLabelStatement.

Supported unnamed scope types (address-based name) include: SgDeclarationScope, SgAssociateStatement, SgJavaForEachStatement, SgFunctionParameterScope, SgAdaPackageSpec, SgAdaPackageBody, SgAdaTaskSpec, SgAdaTaskBody, SgAdaProtectedSpec, SgAdaProtectedBody, SgAdaGenericDefn, SgAdaAcceptStmt, SgJovialForThenStatement, SgMatlabForStatement, SgBasicBlock, SgCatchOptionStmt, SgDoWhileStmt, SgForStatement, SgGlobal, SgIfStmt, SgSwitchStatement, SgWhileStmt, SgFortranDo, SgForAllStatement, SgRangeBasedForStatement.

Parameters
scopeA pointer to a constant SgScopeStatement node whose name is to be retrieved. This pointer must not be NULL.
Returns
A string containing the name associated with the given scope. For named scopes, this is the symbolic name derived from the associated declaration. For unnamed scopes, this is a string representation of the node's pointer address. The initial default value is "undefined_name", which is only returned if no case is matched (though in practice an unmatched case triggers an abort).
Warning
If the variant type of the scope node does not match any recognized case in the switch statement, the function prints an error message to standard output and calls ROSE_ABORT(), terminating the program. This function should not be called with scope node types that are not explicitly handled.
Precondition
scope must not be NULL. A failed ROSE_ASSERT will be triggered if a NULL pointer is passed.
scope must be a valid, fully constructed SgScopeStatement node with a correct variant type set.
For named scope types, the associated declaration node accessible via the scope's getter methods must also be valid and non-NULL.
Postcondition
The returned string is non-empty. For named scopes it reflects the symbolic identifier of the scope. For unnamed scopes it reflects the memory address of the scope node formatted as a string.
The input scope node and its associated AST structures are not modified by this function.
Note
The function uses const_cast when passing the scope pointer to StringUtility::numberToString() for unnamed scopes, as that utility function does not accept a const pointer. This cast does not result in any modification of the pointed-to object.
This function is one of several overloaded get_name() functions in SageInterface, each handling a different category of AST node.
Support for SgTemplateClassDefinition was added in June 2011, SgTemplateFunctionDefinition in September 2012, and SgDeclarationScope in July 2017.

string SageInterface::get_name ( const SgStatement * stmt)

Retrieves a human-readable name string for a given SgStatement node.

This function attempts to determine a meaningful name for a given statement node in the ROSE compiler's Abstract Syntax Tree (AST). It operates through a hierarchical dispatch mechanism:

  1. If the statement is a declaration statement (SgDeclarationStatement), the function delegates to the overloaded get_name() variant that handles declaration statements.
  2. If the statement is a scope statement (SgScopeStatement), the function delegates to the overloaded get_name() variant that handles scope statements.
  3. For all other statement types, a switch on the statement's variant type is used. Currently, the SgLabelStatement case is explicitly handled by returning the label's string representation. All other statement types fall through to the default case, which returns the class name of the statement node via class_name().

If none of the above conditions yield a specific name, the function returns the string "undefined_name" as a fallback, though in practice the default switch case ensures that at minimum the class name is returned for unrecognized statement types.

Parameters
stmtA pointer to a constant SgStatement node for which the name is to be retrieved. Must not be NULL.
Returns
A string representing the name of the given statement. This may be:
  • The name derived from the declaration (if stmt is a declaration statement),
  • The name derived from the scope (if stmt is a scope statement),
  • The label string (if stmt is an SgLabelStatement),
  • The class name of the statement node (for all other statement types),
  • "undefined_name" if no other name can be determined (fallback only).
Warning
Passing a NULL pointer for stmt will trigger a failed assertion (ROSE_ASSERT), causing the program to abort. Always ensure that stmt is a valid, non-NULL pointer before calling this function.
Precondition
stmt must not be NULL.
stmt must point to a valid, fully constructed SgStatement node within the ROSE AST.
Postcondition
The returned string is a non-empty string representing the name or class name of the given statement node.
The input statement node is not modified by this function.
Note
This function is part of the SageInterface utility namespace in the ROSE compiler infrastructure, which provides helper functions for querying and manipulating AST nodes.
The function uses isSgDeclarationStatement(), isSgScopeStatement(), and isSgLabelStatement() dynamic cast utilities provided by ROSE to determine the concrete type of the statement node.
For SgLabelStatement nodes, the label name is obtained via get_label().str(), providing the actual label identifier as defined in the source code.
Several statement variant cases (e.g., V_SgBreakStmt, V_SgReturnStmt) are present in the source as commented-out code, indicating they were considered for explicit handling but are currently handled by the default case returning the class name.

string SageInterface::get_name ( const SgSupport * node)

Returns a human-readable name string for a given SgSupport IR node.

This function is primarily intended for debugging purposes and provides a general mechanism to retrieve a descriptive name string for any IR node derived from SgSupport in the ROSE compiler infrastructure. The function uses a switch statement on the node's variant type (obtained via variantT()) to dispatch to the appropriate name-retrieval logic for each supported IR node kind.

For each recognized node type, the function constructs a name string that may include a fixed prefix tag (e.g., "_pragma_string_", "_file_", "_template_argument_") combined with additional identifying information extracted from the node, such as a file name, pragma text, type name, group name, or block name. For node types that are not explicitly handled, the function falls through to a default case that prints a diagnostic message and returns the string "default name".

Supported node types include, but are not limited to:

  • SgInitializedName: returns the variable or parameter name.
  • SgPragma: returns a string prefixed with "_pragma_string_" followed by the pragma text.
  • SgProject: returns "_project_".
  • SgSourceFile and SgBinaryComposite: returns "_file_" followed by the file name.
  • SgSymbolTable: returns "_symbol_table_".
  • SgStorageModifier: returns "_storage_modifier_".
  • Sg_File_Info: returns "_file_info_".
  • SgTemplateArgument: returns "_template_argument_" with type, expression, initialized name, or template declaration name appended depending on the argument type.
  • SgTypeModifier: returns "_type_modifier_" followed by the display string.
  • SgNameGroup: returns "_name_group_" followed by the group name.
  • SgDataStatementGroup: returns "_data_statement_group_".
  • SgDataStatementObject: returns "_data_statement_object_".
  • SgDataStatementValue: returns "_data_statement_value_".
  • SgCommonBlockObject: returns "_common_block_object_" followed by the block name.
  • SgFormatItem: returns "_format_item_".
  • SgFormatItemList: returns "_format_item_list_".
  • SgRenamePair: returns a combination of local name and use name with "_rename_pair_" suffix.
  • SgName: returns "_name_" followed by the string content of the name node.
  • SgTemplateParameter: returns "_template_parameter_" with a suffix indicating the parameter kind (type_parameter, nontype_parameter, or template_parameter), and for nontype parameters appends the unparsed string representation.
  • SgBaseClass: returns "_base_class_" followed by the access modifier and the base class name.

For SgTemplateArgument nodes with a nontype_argument type, the function handles the case where either an expression or an SgInitializedName is associated with the argument, but not both.

Parameters
nodeA pointer to a constant SgSupport IR node for which the name is to be retrieved. Must not be NULL.
Returns
A std::string containing a descriptive name for the given IR node. Returns "undefined_name" as the initial default, "default name" if the node type is not explicitly handled, or a type-specific string for recognized node types.
Warning
If the node pointer is NULL, the function will trigger a failed assertion (ROSE_ASSERT) and abort execution. Do not pass a NULL pointer.
For SgTemplateArgument nodes with a nontype_argument type, exactly one of get_expression() or get_initializedName() must be non-NULL. If both are NULL or both are non-NULL, assertion failures will occur.
For unrecognized or unhandled node types, the function prints a diagnostic message to standard output and returns "default name" without aborting. This behavior is intended for debugging and may indicate incomplete coverage of IR node types.
For SgTemplateArgument nodes with an unknown argumentType, the function calls ROSE_ABORT() and terminates execution.
For SgTemplateParameter nodes with an unknown parameterType, the function calls ROSE_ABORT() and terminates execution.
Precondition
node must not be NULL.
For SgTemplateArgument nodes of nontype_argument kind, exactly one of get_expression() or get_initializedName() must return a non-NULL pointer.
For SgBaseClass nodes, get_base_class() and get_baseClassModifier() must return non-NULL pointers.
Postcondition
The returned string is a non-empty std::string describing the node.
The input node and the ROSE IR are not modified by this function.
Note
This function is intended primarily as a debugging utility and is not guaranteed to produce unique names for all IR nodes.
The function recursively calls other overloads of get_name() (e.g., for SgType, SgExpression, SgDeclarationStatement, and SgInitializedName) to construct composite name strings for template arguments and base classes.
Support for SgBinaryComposite is conditionally compiled and is only available when ROSE_ENABLE_BINARY_ANALYSIS is defined.

string SageInterface::get_name ( const SgSymbol * symbol)

Returns a human-readable name string for a given symbol node in the ROSE IR.

This function retrieves the name associated with a given SgSymbol node in the ROSE Intermediate Representation (IR). It is primarily intended for debugging purposes and serves as a general-purpose utility to obtain a descriptive name for any symbol node. The function calls the virtual get_name() method on the symbol object, which dispatches to the appropriate derived class implementation.

If the provided symbol is an alias symbol (i.e., an instance of SgAliasSymbol), the returned string is augmented with the prefix "_ALIAS" to distinguish it from non-alias symbols. In all cases, the returned string is further suffixed with "_symbol_" to indicate that the name originates from a symbol node.

The function leverages the polymorphic virtual get_name() mechanism of the ROSE IR symbol hierarchy, ensuring that the most derived and appropriate name is retrieved regardless of the specific symbol subtype.

Parameters
symbolA pointer to a constant SgSymbol node whose name is to be retrieved. Must not be NULL.
Returns
A string representing the name of the symbol. The returned string is composed of the symbol's own name (as returned by its virtual get_name() method), optionally followed by "_ALIAS" if the symbol is an alias symbol, and always followed by the suffix "_symbol_".
Warning
Passing a NULL pointer for the symbol parameter will trigger an assertion failure (ROSE_ASSERT), causing the program to abort. Always ensure the symbol pointer is valid before calling this function.
Precondition
The parameter symbol must be a non-NULL pointer to a valid SgSymbol object within the ROSE IR.
Postcondition
The returned string is a non-empty string containing the symbol's name with appropriate suffixes appended. The original symbol node is not modified by this function.
Note
This function is primarily intended for use in debugging scenarios where a quick, readable representation of a symbol node is needed. The "_symbol_" suffix is always appended to the result to help identify the source as a symbol node rather than a declaration or other IR node type. The "_ALIAS" infix is only present when the symbol is identified as an SgAliasSymbol.

string SageInterface::get_name ( const SgType * type)

Returns a human-readable string name representing a given ROSE IR type node.

This function produces a descriptive string name for any SgType-derived node in the ROSE Intermediate Representation (IR). It is primarily intended as a debugging utility to allow developers to quickly identify and inspect type nodes during program analysis or transformation tasks.

The function first checks whether the given type is a named type (SgNamedType). If so, it retrieves and returns the declared name of that type directly. For all other type categories, the function uses a switch statement on the type's variant tag to construct a descriptive name string. The following cases are handled explicitly:

  • SgPointerType: Returns a string of the form "pointer_to_" concatenated with the recursively resolved name of the base type.
  • SgReferenceType: Returns a string of the form "reference_to_" concatenated with the recursively resolved name of the base type.
  • SgArrayType: Returns a string of the form "array_of_" concatenated with the recursively resolved name of the base type.
  • SgModifierType: Returns a string formed by concatenating the modifier type's modifier name (obtained via get_name on the SgTypeModifier) with the recursively resolved name of the base type.
  • SgTemplateType: Returns a string of the form "templateType_" concatenated with the template type's name.
  • Default (all other types): Returns the class name of the type node as reported by the ROSE IR class_name() method.

For compound types such as pointers, references, arrays, and modifier types, the function recurses into the base type to build a fully descriptive name string.

Parameters
typeA pointer to a constant SgType node for which the name is to be retrieved. Must not be NULL.
Returns
A std::string containing a human-readable representation of the given type. The exact format of the returned string depends on the specific type variant, as described in the detailed description above.
Warning
This function is intended primarily for debugging purposes and should not be relied upon for producing canonical or language-standard type name strings. The returned string format may change across ROSE versions.
Precondition
The parameter type must not be NULL. A failed assertion will be triggered if a NULL pointer is passed.
The type pointer must point to a valid, fully constructed SgType node within a well-formed ROSE AST.
Postcondition
The returned string is a non-empty, human-readable description of the type.
The input type node and the AST are not modified by this function.
Note
For named types (SgNamedType and its subclasses such as SgClassType and SgEnumType), the actual declared name is returned rather than a prefixed descriptive string.
For unrecognized or unhandled type variants, the ROSE class_name() method is used as a fallback, which returns the C++ class name of the IR node.
This function uses recursive calls to resolve the names of base types in compound type constructs. Deeply nested compound types will result in correspondingly deep recursion.
