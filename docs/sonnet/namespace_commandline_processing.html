Parses a space-delimited command line string into a list of individual argument tokens.

This function takes a single string representing a command line and splits it into individual tokens by using space characters as delimiters. It iterates through the input string, locating each space-separated substring and appending it to a result container. The splitting is performed using repeated calls to std::string::find to locate space boundaries, advancing the start position past each found delimiter. When no further space is found (i.e., std::string::npos is returned), the remaining portion of the string up to its end is treated as the final token.

The algorithm uses unsigned long integer indices to track substring boundaries, which avoids potential issues with signed/unsigned comparison when checking against std::string::npos. Each discovered token is pushed onto the result container in order of appearance.

This function is useful for converting a flat command line string, such as one read from a configuration file or environment variable, into a structured argument list compatible with further command line processing utilities.

Parameters
commandlineA space-delimited string representing a command line. Each space-separated segment is treated as a distinct argument token. Multiple consecutive spaces will result in empty string tokens being inserted into the returned list.
Returns
A Rose_STL_Container of strings, where each element corresponds to one space-delimited token from the input command line string. The tokens appear in the same order as in the original string. If the input string is empty, an empty container is returned.
Warning
Consecutive space characters in the input string will produce empty string tokens in the output list. No trimming or collapsing of whitespace is performed.
Only single space characters are used as delimiters. Other whitespace characters such as tabs or newlines are not treated as separators and will be included as part of the adjacent token.
Precondition
The input parameter commandline must be a valid std::string object. It may be empty, in which case the function returns an empty container without entering the parsing loop.
Postcondition
The returned container contains one entry for each space-delimited token found in the input string, in the order they appear. The original input string is not modified.
Note
This function was updated based on a fix suggested by Milind to correctly support astMerge in compilation of multiple files. The substring start index is now advanced to one position past the found space delimiter rather than directly to the delimiter position, preventing off-by-one errors in token extraction.
The use of unsigned long int for substring indices is intentional, as it prevents the comparison against std::string::npos from always evaluating to false when using shorter integer types.

This function checks whether the provided command-line argument string is one of a known set of options that must be followed by an additional parameter value. It is used during command-line processing to prevent the subsequent parameter from being misidentified as a source file name intended for EDG parsing and translation.

The function performs a series of equality comparisons against a comprehensive list of recognized option strings. These include standard compiler options (such as "-o", "-include", "-isystem"), Darwin-specific options (such as "-framework", "-dylib_file"), ROSE-specific options (such as "-rose:output", "-rose:verbose", "-rose:log", and numerous dotgraph and AST I/O options), Intel compiler options (such as "-fp-model", "-diag-disable"), ifort options (such as "-align", "-warn", "-check"), and GCC options (such as "--param").

It also calls isOptionTakingThirdParameter to capture options that require even more subsequent parameters, since those necessarily consume a second parameter as well.

This function is part of the ROSE compiler infrastructure and is typically invoked during the parsing phase of command-line argument handling to correctly segment the argument list before passing it to the front-end or back-end compiler.

  1. Checks if the suffix matches a known Ada file name suffix via isAdaFileNameSuffix().
  2. Checks if the suffix matches a known Fortran file name suffix via isFortranFileNameSuffix().
  3. Checks if the suffix matches a known Jovial file name suffix via isJovialFileNameSuffix().

  6. Iterates over extraCppSourceFileSuffixes to check for additional C++ source file suffix matches using the same trailing-substring comparison.

If any of these checks succeeds, the function returns true immediately. If none of the checks match, the function returns false.
