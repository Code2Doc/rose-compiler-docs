void Outliner::appendIndividualFunctionCallArgs ( const ASTtools::VarSymSet_t & syms,
const std::set< SgInitializedName * > varUsingOriginalType,
SgExprListExp * e_list )

Appends individual function call arguments to an expression list for outlined functions.

This function iterates through a set of variable symbols and constructs appropriate function call arguments for each variable, appending them to the provided expression list. The argument construction differs based on the programming language (Fortran vs C/C++) and whether the variable should use its original type or be passed by reference using the address-of operator.

For Fortran, variables are passed by reference by default, so the variable reference is appended directly. For C/C++, the function determines whether to pass the variable by value (for classic translation with read-only variables) or by reference using the address-of operator (the conservative default approach for outlined functions).

Parameters
symsA constant reference to a set of variable symbols (VarSymSet_t) representing the variables that need to be passed as arguments to the outlined function.
varUsingOriginalTypeA set of SgInitializedName pointers indicating which variables should use their original type (passed by value) rather than being passed by reference via address-of operator. This typically includes arrays which are naturally passed by reference, or read-only variables in classic outlining mode.
e_listA pointer to an SgExprListExp object where the constructed function call arguments will be appended. Must not be null.
Warning
The function uses const_cast to remove constness from variable symbols when building variable reference expressions. This may lead to unexpected behavior if the underlying symbol is modified.
Precondition
The syms parameter must contain valid, non-null variable symbols.
The e_list parameter must point to a valid, initialized SgExprListExp object.
Each variable symbol in syms must have a valid declaration (SgInitializedName).
Postcondition
All variables in syms will have corresponding arguments appended to e_list.
The order of arguments in e_list corresponds to the iteration order of syms.
Note
The behavior differs based on the Outliner::enable_classic flag. When enabled and the variable is in varUsingOriginalType, the variable is passed by value. Otherwise, the address-of operator is applied for C/C++ code.
Array types require special consideration as they can only be passed by reference and do not need additional addressing or dereferencing operations.
This function is part of the ROSE compiler infrastructure's outlining mechanism.

◆ collectVars()

void Outliner::collectVars ( const SgStatement * s,
ASTtools::VarSymSet_t & syms )

Collects variables that need to be passed as parameters to an outlined function.

This function performs variable analysis to determine which variables must be passed as parameters when outlining a code region into a separate function. The algorithm uses set operations to compute the necessary variables based on their usage and declaration scope.

The algorithm works as follows:

  1. Compute U: the set of all variable symbols referenced within statement s
  2. Compute L: the set of all variable symbols declared locally within statement s
  3. Compute U - L: variables used but not locally declared (non-local references)
  4. If outlining to a new file, all non-local variables are passed as parameters
  5. Otherwise, compute Q: locally visible variables in the enclosing function, then compute (U - L) intersection Q to get only the variables that need explicit parameter passing (excluding global variables)
Parameters
sPointer to the SgStatement representing the code region to be outlined. This statement must be contained within a valid function definition.
symsReference to a VarSymSet_t that will be populated with the variable symbols that need to be passed as parameters to the outlined function. Any existing contents will be replaced.
Warning
The behavior differs based on the Outliner::useNewFile flag. When true, global variables are passed as parameters rather than using extern declarations, which may be less efficient.
Precondition
The statement s must not be null.
The statement s must be contained within a valid SgFunctionDefinition.
The AST containing s must be properly formed and traversable.
Postcondition
The syms set contains all variable symbols that must be passed as parameters to the outlined function.
If useNewFile is true, syms equals U - L (all non-local variables).
If useNewFile is false, syms equals (U - L) intersection Q (non-local variables that are locally visible in the enclosing function).
Note
When Outliner::useNewFile is true, a more optimal approach would be to identify global variables separately and generate extern declarations for them instead of passing them as parameters.
Debug output is generated via dump() calls to show intermediate sets during the computation process.

Generates a unique function argument name based on the source file of a statement.

This function creates a unique identifier string for outlined function arguments by combining a file-specific prefix with a hash value derived from the source filename. The generated name ensures uniqueness across different source files by incorporating both a sequential counter and a hash of the filename.

The algorithm works as follows:

  1. Retrieves the raw filename from the statement's source location information
  2. Obtains the next available name from a global outlined argument name generator using the filename as a key
  3. Appends a hash value of the filename converted to unsigned long
  4. Appends a double underscore suffix as a delimiter
Parameters
stmtPointer to a constant SgStatement object from which the source file information is extracted. This statement must have valid file information associated with its start of construct.
Returns
A string containing the generated unique function argument name, formatted as: [prefix][hash]__
Warning
The function will trigger an assertion failure if the statement's file information (Sg_File_Info) is null.
Precondition
The parameter stmt must not be null.
The statement must have valid source location information with a non-null Sg_File_Info object at its start of construct.
The global variable g_outlined_arg_names must be properly initialized.
Postcondition
The returned string is non-empty and ends with double underscores.
The global g_outlined_arg_names counter for the given filename is incremented.
Note
This function is part of the Outliner class and is typically used during code outlining transformations to generate unique parameter names for outlined functions.
The hash function hashStringToULong is used to provide additional uniqueness based on the full filename path.

string Outliner::generateFuncName ( const SgStatement * stmt)

Generates a unique function name for an outlined code region.

This function creates a unique identifier string to be used as the name for an outlined function. The naming strategy differs based on whether dynamic loading (dlopen) is enabled. When dlopen is used, the function generates names using per-file counters combined with the source file name and line number to ensure uniqueness across multiple header files included in a single compilation unit. When dlopen is not used, a global counter combined with a hash of the filename is employed instead.

The algorithm performs the following steps:

  1. Generates a numeric prefix using either a per-file counter (dlopen mode) or a global counter (non-dlopen mode).
  2. Extracts file information from the statement's source location.
  3. In dlopen mode: appends the sanitized base filename and line number. In non-dlopen mode: appends a hash of the raw filename.
  4. Sanitizes the filename by replacing invalid identifier characters (hyphens and dots) with underscores.
Parameters
stmtPointer to the SgStatement representing the code region being outlined. Must not be null and must have valid source position information (Sg_File_Info).
Returns
A unique string suitable for use as an outlined function name. The format varies based on the use_dlopen flag:
  • With dlopen: "<counter>_<sanitized_filename>_<line_number>"
  • Without dlopen: "<counter><filename_hash>__"
Warning
The function assumes that the statement has valid source position information. If get_startOfConstruct() returns invalid data, undefined behavior may occur.
Precondition
The parameter stmt must be a valid, non-null pointer to an SgStatement.
The statement must have valid Sg_File_Info associated with its start of construct.
The global variables g_outlined_func_names and g_outlined_func_names2 must be properly initialized.
Postcondition
A unique function name string is returned that can be used as a valid C/C++ identifier.
The appropriate counter (global or per-file) is incremented.
Note
The function preserves the file suffix in dlopen mode to differentiate between header and source files with the same base name.
Characters that are invalid in C/C++ identifiers (specifically '-' and '.') are replaced with underscores to ensure the generated name is a legal identifier.
The use_dlopen flag is a member variable that determines the naming strategy used.

Generates packing statements to wrap outlined function parameters into a single data structure.

This function creates the necessary statements to pack multiple variables into either a structure or an array of void pointers for passing to an outlined function. The packing mechanism supports two modes: structure-based wrapping and array-of-pointers wrapping.

In structure-based wrapping mode, each variable is assigned to a corresponding field in the wrapper structure. Variables that need to be passed by reference have their addresses taken and stored in pointer-type fields (suffixed with "_p"). Array members are handled specially by copying each element individually.

In the default array-of-pointers mode, all variables are stored as void pointers in an array, with each variable's address cast to void pointer type.

The generated wrapper variable declaration and all packing assignment statements are inserted immediately before the target statement in the AST.

Parameters
targetThe statement before which the packing statements will be inserted. This is typically the outlined block that will be moved to the outlined function.
symsA set of variable symbols representing all variables that need to be packed for the outlined function. The set is iterated in reverse order.
pdsymsA subset of syms containing variables that should be passed by pointer (i.e., variables that need their addresses taken rather than their values).
struct_declThe class declaration for the wrapper structure when using structure-based wrapping. Must not be NULL if useStructureWrapper is true. Defaults to NULL.
Returns
The name of the generated wrapper variable as a string. This name is generated by the generateFuncArgName function based on the target statement.
Warning
The function assumes that the target statement has a valid scope. An assertion failure will occur if target->get_scope() returns NULL.
When useStructureWrapper is true, struct_decl must not be NULL, otherwise an assertion failure will occur.
The wrapper_symbol must have a non-NULL parent after creation, which is verified by an assertion.
Precondition
The target parameter must be a valid SgStatement with a non-NULL scope.
If useStructureWrapper is enabled, struct_decl must point to a valid class declaration with a defining declaration and definition.
The syms set should contain valid variable symbols with proper declarations.
The pdsyms set should be a subset of syms.
Postcondition
A wrapper variable declaration is inserted before the target statement.
For each variable in syms, a corresponding packing assignment statement is inserted before the target statement.
The AST is modified with new nodes for the wrapper declaration and assignments.
Note
When the syms set is empty (var_count == 0), the function returns early with just the wrapper name without generating any declarations or statements.
For pointer members with void* type in structure wrapping mode, an explicit cast to void* is applied to the right-hand side expression.
Array-type members in structure wrapping mode are handled by build_array_packing_statement which copies each array element individually.
The useStructureWrapper flag is a class member that determines which packing mode is used.
