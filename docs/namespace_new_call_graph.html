int NewCallGraph::buildCallGraph ( SgProject * project)

Constructs a call graph for a given SgProject.

This function performs a traversal of the provided SgProject to identify and map function calls within the source code. It utilizes a CallGraph traversal mechanism to visit the nodes of the AST in preorder. Once the traversal is complete, the collected call information is used to generate a call graph file.

Parameters
projectA pointer to the SgProject instance representing the source code to be analyzed.
Returns
An integer status code representing the result of the operation. Returns 0 upon successful completion.
Precondition
project must not be NULL.
Postcondition
A call graph file is generated based on the data collected from the project traversal.
Note
The function uses ROSE_ASSERT to validate the project pointer. The implementation contains several if 0 blocks which are currently inactive and do not affect the execution flow.

void NewCallGraph::generateCallGraphFile ( SgProject * project,
CallGraph & cg )

Generates and updates call graph data in both text and binary file formats.

This function manages the persistence of call graph information. It performs an incremental update by reading an existing binary call graph file, merging it with the current translation unit's data, and writing the updated state back to the binary file. Simultaneously, it generates a human-readable text file ("textCallgraph") for debugging purposes. The process involves acquiring a file lock to ensure atomicity and handles both function nodes (declarations/definitions) and edges (calls) within the graph.

The implementation uses a file locking mechanism via getLock and releaseLock to prevent race conditions during concurrent access. It iterates through existing structures from the binary file to identify nodes or edges that are already represented in the current translation unit, marking them to avoid redundant writes. It also handles the logic for updating a non-defining declaration to a defining declaration if the definition is found in the current unit.

Parameters
projectA pointer to the SgProject containing the source files and AST information.
cgThe CallGraph object containing the maps of nodes and edges to be persisted.
Precondition
project must not be NULL.
project must contain at least one file.
The source file name length must be less than the predefined fileNameLength.
A valid file lock must be obtainable via NewCallGraph::getLock().
Postcondition
The "textCallgraph" file is updated with new and existing graph elements.
The "binaryCallGraph" file is updated with the merged call graph data.
The file lock is released.
Warning
The text file implementation is currently not fully consistent with the binary file format (as noted in the implementation).
If the binary file or text file fails to open, the function calls ROSE_ABORT(), terminating the program.
Uses memcpy, so ensure that string lengths do not exceed the fixed-size buffers in CallGraphFileStructure.
Note
This function assumes that there is only one source file per invocation of the ROSE tool on the command line.

void NewCallGraph::generateDotFile ( string binaryFilename)

Generates a DOT file representation of the call graph from a binary file.

This function reads a previously saved call graph structure from a specified binary file. It iterates through the loaded vector of call graph file structures, distinguishing between nodes (functions) and edges (function calls). For each entry, it extracts relevant metadata such as function names and file names. While the current implementation extracts these strings into local variables, it serves as the foundation for constructing a Graphviz-compatible DOT format string.

Parameters

Precondition
The file specified by binaryFilename must exist and be a valid binary representation of a vector<CallGraphFileStructure>.
Postcondition
If the file is successfully read, the function processes all entries within the call graph vector. If the file cannot be read, the function returns without performing any processing.
Note

int NewCallGraph::getLock ( )

Acquires a file-based lock to ensure exclusive access to the call graph process.

This function attempts to create and open a lock file named "rose_callgraph_lockfile.lock" using the O_CREAT and O_EXCL flags. This mechanism is used to prevent multiple instances of the call graph generation from running concurrently and interfering with each other. The function implements a retry loop with a timeout mechanism. It uses a counter to track attempts and will wait for a specified tolerance (userTolerance) before notifying the user that a lock file might need manual removal. The implementation uses platform-specific sleeping via ifdef _MSC_VER to handle both Windows and POSIX-compliant systems.

Returns
An integer representing the file descriptor of the successfully opened lock file. If the file descriptor is -1, an error occurred during the opening process.
Precondition
The process must have sufficient filesystem permissions to create and write to a file in the current working directory.
Postcondition
If successful, a file descriptor is returned and a lock file exists on the filesystem, preventing other processes from acquiring the same lock.
Warning
If the lock file exists from a previous crashed session, the function will loop and wait. Users may need to manually delete the lock file (e.g., by running "make clean") if the problem persists.
Note
The function uses a hardcoded filename "rose_callgraph_lockfile.lock".
The retry logic includes a counter reset to prevent overflow during long-running automated tests.

vector< CallGraphFileStructure > * NewCallGraph::readCallGraphFile ( string binaryFilename)

Reads a call graph structure from a binary file.

This function opens a specified binary file, determines its size, and reads the contents directly into a dynamically allocated vector of CallGraphFileStructure objects. The function calculates the number of entries based on the file size and the size of the CallGraphFileStructure struct, then performs a bulk read from the file stream into the vector's underlying memory.

Parameters
binaryFilenameThe path to the binary file containing the call graph data.
Returns
A pointer to a dynamically allocated vector of CallGraphFileStructure containing the data read from the file. Returns NULL if the file cannot be opened or does not exist.
Warning
The caller is responsible for managing the memory of the returned pointer and must delete the allocated vector to prevent memory leaks.
Precondition
The file specified by binaryFilename must exist and be a valid binary file containing data that is a multiple of the size of CallGraphFileStructure.
Postcondition
If the function returns a non-NULL pointer, the file stream is closed and a new vector is allocated on the heap containing the file contents.
Note
The function uses ROSE_ASSERT to verify that the file size is an exact multiple of the size of the Call/GraphFileStructure structure. The implementation uses ifstream::ate to seek to the end of the file initially to compute the file size.

void NewCallGraph::releaseLock ( int fd)

Releases the call graph lock by closing the file descriptor and removing the lock file.

This function performs the cleanup process required to release a system-level lock. It closes the provided file descriptor associated with the lock and attempts to delete the physical lock file named "rose_callgraph_lockfile.lock" from the file system. If the verbosity level of SgProject is set to 0 or higher, a notification message is printed to the standard output.

Parameters
fdThe file descriptor representing the open lock file that needs to be closed.
Precondition
The file descriptor fd must be a valid, open file descriptor previously obtained during the locking process.
Postcondition
The file descriptor fd is closed, and the file "rose_callgraph_lockfile.lock" is removed from the filesystem if it existed.
Note
This function relies on the standard C library functions close and remove. The removal of the lock file is an attempt and does not check if the file was actually present or if the deletion failed due to permissions.
