Adds constructor initializers from a variable declaration statement to a list.

This function inspects a given SgStatement to determine if it is a variable declaration. If it is, the function iterates through all variables declared in that statement. For each variable, it checks if there is an associated constructor initializer. If the initializer is a valid constructor initializer (as determined by isGoodCtorInit), it is inserted at the beginning of the provided in_list.

Parameters

stmtA pointer to the SgStatement to be inspected for variable declarations and initializers.
Precondition
stmt should not be a null pointer.
Postcondition
If the statement contains valid constructor initializers, they will be prepended to the objs list.
Note

Identifies and collects objects allocated within a specific block of statements.

This function traverses a given block of statements (such as a basic block or a for-loop) and collects all objects or variables that are allocated or used within that scope, up to a specified stopping statement. For basic blocks, it also checks the parent node (e.g., for-loops, while-loops, or if-statements) to include variables from loop tests or conditional expressions. If an if-statement is SC-generated, it further traverses the conditional and potentially the first statement of the block to find temporary variables.

Returns
An in_list containing the collection of objects/variables identified during the traversal.

◆ buildDestructorExpr()

SgExpression * buildDestructorExpr ( SgNode * n)

Constructs an expression representing a destructor call for a given node.

This function analyzes the context of a provided SgNode to determine the appropriate object reference for a destructor call. It traverses the AST hierarchy to identify if the node is part of an initialized name, a constructor initializer, or a class declaration. Depending on the identified context, it builds either a dot-access expression (for existing instances) or a reference expression. Finally, it wraps the reference in a function call expression representing the destructor invocation with an empty parameter list.

Parameters
nThe SgNode representing the element whose destructor needs to be constructed. This node is used to trace back to the relevant initialized name or class declaration.
Returns
A pointer to an SgFunctionCallExp representing the destructor call.
Precondition
The input node n must be part of a valid AST structure where the parentage can be traversed to find an initialized name, a constructor initializer, or a class declaration.
Postcondition
The returned SgFunctionCallExp has its parameters set to an empty SgExprListExp, and the reference expression (the receiver of the call) has its parent set to the newly created function call expression.
Warning
If the function cannot identify a valid context (i.e., the node is not an initialized name, a constructor initializer, or a class declaration), the function calls ROSE_ABORT(), terminating the program.
Note
The implementation relies on helper functions such as isSgInitializedName, isSgConstructorInitializer, isSgClassDeclaration, buildDtorDotExpr, and buildDtorRefExpr.

◆ moveForInitializers()

void moveForInitializers ( SgForStatement * forStmt)

Moves the initialization statements of a for-loop into a newly created basic block.

This function performs a structural transformation on a given for-loop statement. It extracts the initialization statements from the for-loop and moves them into a new SgBasicBlock. The new block is then inserted into the program flow at the original position of the for-loop. During this process, the function also updates the parent-child relationships of the statements and modifies the storage modifiers of any declaration statements found within the initializers to ensure they are no longer scoped strictly to the loop header.

Parameters
forStmtA pointer to the SgForStatement whose initialization statements are to be moved.
Precondition
forStmt must not be null and must be a valid SgForStatement object.
Postcondition
The initialization statements of forStmt are cleared from the for-loop.
A new SgBasicBlock is created and placed at the original position of forStmt.
The initialization statements are now children of the new SgBasicBlock.
Any SgDeclarationStatement within the moved initializers will have its storage modifier reset to default.
Note
This transformation effectively changes the scope of the loop's initialization statements by placing them in a preceding basic block.
