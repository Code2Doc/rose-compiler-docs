void buildTokenStreamFrontier ( SgSourceFile * sourceFile,

Builds the token stream frontier for a given source file to facilitate token-based unparsing.

Constructs the token stream frontier for a given source file to facilitate precise unparsing.

This function identifies the "frontier" of nodes in the AST that can be unparsed using token subsequences rather than the AST itself. It performs several critical steps:

  1. Detects the frontier using simple frontier detection algorithms.
  2. Identifies macro expansions that should be unparsed as AST transformations.
  3. Detects the frontier for token stream mapping.
  4. Handles redundant mappings where multiple IR nodes (e.g., multiple SgVariableDeclaration nodes) map to the same token subsequence. It ensures that if any node in a redundant group requires AST-based unparsing, the entire group is reverted to AST unparsing to prevent duplication or inconsistent unparsing.
  5. Updates the source file with sets of redundant token endings and associated multimaps to allow the unparser to avoid duplicate output.
Parameters
sourceFileA pointer to the SgSourceFile being processed. This file must have an initialized token subsequence map.
traverseHeaderFilesA boolean flag indicating whether the frontier detection should extend into included header files.
Precondition
sourceFile must not be NULL.
The token subsequence map for sourceFile must be populated and searchable.
The token unparse frontier map for sourceFile must be initialized.
Postcondition
The sourceFile's token unparse frontier map is updated with flags for redundant token subsequences and AST-based unparsing requirements.
The sourceFile is updated with a set of redundant token endings and a multimap of statements associated with those endings.
Note
The function uses if and define directives for various debug and testing modes.
If ROSE_tokenUnparsingTestingMode is true, the function calls buildArtificialFrontier.
The function relies on the existence of a global mapping Rose::tokenSubsequenceMapOfMapsBySourceFile for the provided sourceFile.

This function identifies the "frontier" of nodes in the Abstract Syntax Tree (AST) that can be unparsed using token sequences rather than the AST itself. This is essential for providing a precise generated code representation with minimal differences (diffs) when transformations have occurred. The function performs several stages of detection, including simple frontier detection, macro expansion detection, and full frontier detection. It also handles the normalization of redundant mappings where multiple IR nodes (such as multiple variable declarations) map to the same token subsequence, ensuring that these nodes are unparsed as a consistent group to avoid duplication or inconsistency.

Parameters
sourceFileA pointer to the SgSourceFile being processed. The function relies on the source file containing a valid token subsequence map.
traverseHeaderFilesA boolean flag indicating whether the frontier detection process should extend into included header files.
Precondition
The sourceFile must not be NULL and must have a valid entry in Rose::tokenSubsequenceMapOfMapsBySourceFile.
The sourceFile must contain a valid token subsequence map.
Postcondition
The sourceFile will have its token unparse frontier updated with identified frontier nodes and marked redundant token endings.
The sourceFile will have its redundant token endings set and its redundantly mapped tokens to statement multimap updated.
Note
The function uses if and define directives for various debugging and testing modes (e.g., ROSE_tokenUnparsingTestingMode).
The implementation includes logic to prevent redundant unparsing by identifying and grouping statements that map to the same token sequence end.

vector< stream_element * > getTokenStream ( SgSourceFile * file)

Retrieves the sequence of tokens for a given source file.

This function extracts the token stream associated with a specific SgSourceFile. It retrieves the preprocessor directives and comments list from the provided file object, locates the attributes corresponding to the file's name, and converts the underlying list of tokens into a vector for efficient integer-based indexing. The function also updates the global token stream size used for mapping sequences to nodes.

Parameters
fileA pointer to the SgSourceFile object from which the token stream is to be retrieved.
Returns
A vector of stream_element pointers representing the sequence of tokens, CPP directives, and comments found in the file.
Precondition
The file parameter must not be NULL.
The file must have a non-null preprocessor directives and comments list.
The preprocessor directives and comments list must contain at least one entry (e.g., the file itself).
The file name must be present in the file's preprocessor information map.
The map mapFilenameToAttributes must be empty at the start of the function execution.
Postcondition
The global variable TokenStreamSequenceToNodeMapping::tokenStreamSize is updated to reflect the size of the retrieved token stream.
Warning
If the resulting token vector is empty, a warning is printed to standard output indicating that the file contains no tokens.
Note
The return type is currently a vector, but the implementation notes that it may transition to a list-based type (LexTokenStreamType) in the future to better support SgToken IR nodes.
The function uses define DEBUG_GET_TOKEN_STREAM to control debug logging via if and endif directives.

This function extracts the token stream associated with a specific SgSourceFile. It retrieves the preprocessor directives and comments list from the provided file, locates the attributes corresponding to the file's name, and extracts the raw token stream. The function converts the internal list-based token stream into a vector of stream elements to allow for efficient integer-based indexing.

Parameters
fileA pointer to the SgSourceFile object representing the source file from which the token stream is to be retrieved.
Returns
A vector of stream_element pointers representing the sequence of tokens, CPP directives, and comments found in the file.
Precondition
The file parameter must not be NULL.
The file must have a non-null preprocessor directives and comments list (file->get_pretokenDirectivesAndCommentsList() != NULL).
The preprocessor directives and comments list must contain at least one entry (size > 0).
The file name must exist as a key within the file's preprocessor directives and comments list.
Postcondition
The returned vector contains the tokens in the order they appear in the source file.
Note
The return type is currently a vector of stream_element*, but it is noted that this may change in the future to support SgToken IR nodes for better integration with ROSE, File I/O, and memory pool management.
If the file is empty and contains no tokens, a warning is printed to stdout, but the function still returns an empty vector.
The global variable TokenStreamSequenceToNodeMapping::tokenStreamSize is updated to reflect the size of the retrieved token stream.

Reconstructs and writes source code to a file from a token stream based on global scope mappings.

This function iterates through the declaration list of the global scope associated with a given source file. It uses a mapping of IR nodes to token sequences to reconstruct the original source text. The algorithm handles the reconstruction by deciding whether to prioritize leading or trailing whitespace/tokens based on the preferTrailingWhitespaceInOutput flag. It manages shared token sequences between nodes to avoid redundant output and handles the edge cases of the first and last declarations to ensure a continuous and accurate reconstruction of the source file content.

Parameters
sourceFileA pointer to the SgSourceFile object representing the source file being processed.
tokenVectorA vector of stream_element pointers containing the actual token data and lexemes.
tokenStreamSequenceMapA map associating SgNode pointers to their corresponding TokenStreamSequenceToNodeMapping, which contains the indices for leading whitespace, token subsequences, and trailing whitespace.
preferTrailingWhitespaceInOutputA boolean flag indicating the strategy for reconstruction: if true, the function prioritizes outputting trailing whitespace; if false, it prioritizes leading whitespace.
Precondition
sourceFile must not be NULL and must contain a valid global scope.
The tokenStreamSequenceMap must contain valid mappings for the nodes present in the global scope's declaration list.
Postcondition
A new file is created on the file system with a name derived from the source file's name, containing the reconstructed source code.
Note
The output filename is prefixed with "token_trailing_" or "token_leading_" depending on the preferTrailingWhitespaceInOutput parameter.
The function uses ROSE_ASSERT to validate the existence of the global scope and the validity of token mappings.

Replaces all occurrences of a search string with a replacement string within a target string.

This function performs an in-place modification of the provided subject string. It iteratively searches for the occurrence of the search string and replaces it with the replace string. The implementation resets the search position to the beginning of the string after each replacement to ensure all instances are captured.

Parameters
subjectThe string that will be modified in-place.
searchThe substring to be searched for within the subject string.
replaceThe string that will replace each occurrence of the search string.
Warning
If the replace string contains the search string (e.g., replacing "a" with "ab"), this function will enter an infinite loop because the search position is reset to 0 and the new string will be found again.
Precondition
The search string should not be a substring of the replace string to avoid infinite recursion.
Postcondition
The subject string will have all non-overlapping occurrences of search replaced by replace, provided the infinite loop condition is not met.
Note
The current implementation resets pos to 0 after every replacement, which ensures comprehensive replacement but increases complexity and risk of infinite loops.
