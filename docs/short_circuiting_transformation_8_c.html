Creates a conditional expression equivalent to a logical OR operation.

This function transforms a logical OR operation into a conditional (ternary) expression. It constructs a new SgConditionalExp where the condition is the left-hand side of the OR operation, the "true" branch is a constant boolean true value, and the "false" branch is the right-hand side of the OR operation. This effectively implements the logic: (lhs || rhs) is equivalent to (lhs ? true : rhs).

Parameters
orOpA pointer to an SgOrOp object representing the logical OR operation to be converted.
Returns
A pointer to a newly allocated SgConditionalExp representing the equivalent conditional logic.
Precondition
orOp must not be a null pointer.
Postcondition
A new SgConditionalExp is allocated on the heap. The caller is responsible for managing its lifetime.
Note
The function uses a hardcoded boolean true value (1) for the true branch of the conditional. The file and line information for the new expression is set to SgNULL_FILE.

Performs constant folding optimization on if-statements with constant boolean conditions.

This function analyzes a given expression to determine if it is a boolean constant value. If the expression is part of an if-statement and its value is known at compile-time, the function optimizes the control flow by removing the if-statement and replacing it with the appropriate branch (true or false body). The implementation traverses up the AST hierarchy to find an appropriate replacement point in the parent statement or basic block, attempting to collapse redundant single-statement blocks.

Parameters
exprThe SgExpression to be inspected for constant boolean values and potential optimization.
Precondition
expr must not be NULL.
Postcondition
If the condition is a constant true, the if-statement is replaced by its true body, and the false body is deleted. If the condition is a constant false, the if-statement is replaced by its false body (or a new basic block if the false body is null), and the true body is deleted.
Note
The optimization process involves navigating through SgExprStatement and SgIfStmt parents. The implementation includes debug logging via cout that tracks the replacement statement and its parent during the upward traversal of the AST.
This function uses ROSE_ASSERT to ensure the parent of the if-statement is a valid SgBasicBlock.

◆ initialTransformation()

void initialTransformation ( SgNode * n)

Performs an initial AST transformation to handle short-circuiting logic.

This function traverses the Abstract Syntax Tree (AST) starting from the provided node n to identify and transform C++ constructs that utilize short-circuiting operators (e.g., logical AND/OR). The transformation aims to decompose complex conditional expressions into simpler, more explicit control flow structures.

The implementation performs the following operations:

  1. Rewrites logical AND (SgAndOp) and OR (SgOrOp) expressions using rewriteConditionals.
  2. Processes SgIfStmt nodes: if the condition contains short-circuiting logic, it decomposes the condition, potentially splitting variable declarations, and introduces new boolean variables and assignment statements to maintain logic.
  3. Processes SgWhileStmt nodes: moves short-circuiting conditions from the loop test into the loop body.
  4. Processes SgDoWhileStmt nodes: transforms short-circuiting conditions by introducing labels and SgIfStmt structures to ensure correct execution flow.
  5. Processes SgForStatement nodes: handles short-circuiting in the initialization, test, and increment components by moving them into the loop body or reorganizing the parent basic block.
  6. Processes SgVariableDeclaration nodes: if a declaration contains short-circuiting logic, it is split into a declaration and a subsequent assignment statement.
Parameters
nThe root node of the AST subtree to be transformed.
Precondition
The parameter n must be a valid, non-null SgNode pointer representing a valid part of the AST.
Postcondition
The AST subtree rooted at n is modified in-place. Short-circuiting constructs are expanded into explicit control flow statements, and associated variables/assignments are inserted into the appropriate parent basic blocks.
Note
The function relies heavily on ROSE_ASSERT for structural integrity. Significant changes to the AST structure (parent/child relationships) occur during the transformation.
The function uses a static counter for generating unique variable names (e.g., rose_sc_bool_X).

This function transforms a given statement (either an expression statement or a variable declaration) by embedding it within a newly created if-statement structure inside the target basic block. For expression statements, the original statement becomes the condition of the if-statement, which then executes a dummy true-branch. For variable declarations, the declaration is prepended to the body, and the declaration is split into a new assignment expression that serves as the if-statement's condition.

Reduces if statements and comma operators by simplifying control flow based on SC-generated expressions.

This function iterates through all applicable SC (Single Control) expressions found within an SgProject. For each expression, it identifies the associated statement and basic block, then performs structural transformations on the AST. Specifically, it handles the reduction of comma operators (V_SgCommaOpExp) by splitting them into separate statements and the simplification of conditional expressions (V_SgConditionalExp) by transforming them into structured if-statements or direct replacements based on the condition's value. The function also manages the reconstruction of the AST hierarchy, including the creation of new SgBasicBlock nodes and the replacement of existing nodes in the parent statements.

Parameters
prjA pointer to the SgProject containing the AST to be processed.
Returns
True if any transformations were performed (i.e., if any applicable SCs were found and processed), false otherwise.
Precondition
The prj parameter must not be NULL and must contain a valid SgProject structure.
Postcondition
The AST within the provided prj may be modified, with certain expressions replaced by simplified statements or basic blocks.
Note
The function uses a static variable callCount to track the number of times the function has been invoked.
The function relies on the existence of helper functions such as findApplicableSCs, findStatementForExpression, findBasicBlockForStmt, isSgStatement, IsSCGenerated, and ifConstOptimization.
If an unknown variant type is encountered during the processing of a basic block child, the function will trigger an error via AstJSONGeneration and call ROSE_ABORT().
The function utilizes ifdef SCDBG blocks for debugging purposes, which allow for generating intermediate AST JSON snapshots during the optimization process.

SgExprStatement * splitVarDecl ( SgVariableDeclaration * varDecl)

Splits a variable declaration with an initializer into a declaration and a separate assignment expression statement.

This function takes a variable declaration that contains an initializer and transforms it into two distinct parts: a declaration without an initializer and a new expression statement containing an assignment operation. The implementation extracts the first variable from the declaration, identifies the type of initializer (specifically handling SgAssignInitializer and SgConstructorInitializer), and then constructs a new SgAssignOp wrapped in an SgExprStatement. The original initializer is removed from the variable.

Parameters
varDeclA pointer to the SgVariableDeclaration to be split. It is assumed that the declaration contains at least one variable with an initializer.
Returns
A pointer to the newly created SgExprStatement containing the assignment operation.
Precondition
The input varDecl must not be NULL and must contain at least one variable initialized with either a SgAssignInitializer or a SgConstructorInitializer.
Postcondition
The original variable within varDecl will no longer have an initializer (it is set to NULL). A new SgExprStatement is returned which performs the assignment of the original value to the variable.
Note
This function relies on the assumption that the first variable in the declaration is the primary target for the split. If the initializer type is neither an assignment nor a constructor initializer, the function will print an error to stdout and call ROSE_ABORT().
