int Rose::Frontend::Run ( SgProject * project)

Executes the frontend processing for a given Rose project.

This function serves as the primary entry point for running the Rose frontend. It determines the appropriate execution path based on the project configuration. If the project is flagged as Java-only, it delegates the execution to the Java-specific frontend implementation. Otherwise, it proceeds with the standard serial execution path. The resulting status code is both returned and stored within the project object.

Parameters
projectA pointer to the SgProject instance to be processed. The project must not be null.
Returns
An integer status code representing the result of the frontend execution. A value of 0 typically indicates success, while non-zero values indicate errors.
Precondition
project must not be null.
Postcondition
The project's frontend error code is updated with the status returned by the execution path.
Note
This function relies on the internal state of the SgProject to decide between Java-specific and serial execution logic.

int Rose::Frontend::RunSerial ( SgProject * project)

Executes the frontend processing for all files in a project sequentially.

This function iterates through the list of all files contained within the provided SgProject. For each file, it invokes the frontend processing logic. The function tracks the highest error code encountered during the execution of the files. It supports a "keep going" mode via Rose::KeepGoing::g_keep_going, which determines whether exceptions caught during file processing should be handled by setting an error code or by allowing them to propagate. The function also handles signal-based error recovery if configured to do so.

Parameters
projectA pointer to the SgProject containing the list of files to be processed.
Returns
An integer representing the maximum error code encountered during the sequential processing of all files in the project.
Precondition
project must not be null.
Postcondition
The error code of the SgProject is updated to reflect the maximum error code encountered during the execution of the frontend on its files.
Note
The variable status_of_function is declared as volatile to prevent optimization issues where the variable might be clobbered by signals such as longjmp or vfork.
If the global keep_going flag is set and an exception is caught, the function may raise SIGABRT.
