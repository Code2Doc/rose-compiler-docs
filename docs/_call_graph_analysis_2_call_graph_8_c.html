ClassHierarchyWrapper * classHierarchy,

Retrieves the set of function declarations associated with a constructor initializer.

This function identifies the properties (function declarations) that are triggered or relevant to a specific constructor initializer. It utilizes the CallTargetSet::solveConstructorInitializer mechanism to resolve the underlying function declarations. The resulting set of function declarations is then appended to the provided Rose_STL_Container.

Parameters
sgCtorInitA pointer to the SgConstructorInitializer object to be analyzed.
classHierarchyA pointer to the ClassHierarchyWrapper used for hierarchy traversal (currently unused in the implementation).
functionListA reference to a Rose_STL_Container of SgFunctionDeclaration pointers where the discovered properties will be stored.
Precondition
sgCtorInit must not be a null pointer.
Postcondition
The functionList container will contain all function declarations identified by the constructor initializer solver, appended to its existing contents.
Note
Currently, all constructor initializers are handled via the solveConstructorInitializer logic within the CallTargetSet class.

◆ is_function_exists()

SgFunctionDeclaration * is_function_exists ( SgClassDefinition * cls,
SgMemberFunctionDeclaration * memberFunctionDeclaration )

Checks if a specific member function declaration exists within a class definition.

This function iterates through all members of a given class definition to find a function declaration that matches the name and type signature of the provided member function declaration. It performs a deep comparison of the function types using is_functions_types_equal. The search specifically looks for non-pure virtual declarations. If a match is found, it attempts to return the non-defining declaration if available, otherwise the defining declaration.

Parameters
clsA pointer to the SgClassDefinition representing the class to be searched.
memberFunctionDeclarationA pointer to the SgMemberFunctionDeclaration whose existence and signature are being verified against the class members.
Returns
A pointer to the matching SgFunctionDeclaration if found and not pure virtual; otherwise, returns NULL.
Precondition
cls and memberFunctionDeclaration must not be NULL.
Postcondition
The returned pointer, if not NULL, points to a valid SgFunctionDeclaration that is not a pure virtual function.
Note
The function relies on the equality of function types via is_functions_types_equal.
The function uses ASSERT_not_null and ASSERT_require for internal consistency checks.

◆ solveFunctionPointerCallsFunctional()

Rose_STL_Container< SgFunctionDeclaration * > solveFunctionPointerCallsFunctional ( SgNode * node,
SgFunctionType * functionType )

Identifies function declarations matching a specific function type for functional pointer call resolution.

This function performs a lookup to determine if a given SgNode, representing a function declaration, matches the provided functionType based on their mangled names. It specifically checks the first non-defining declaration of the function to see if it aligns with the target type. This is used in the context of resolving calls through function pointers by matching type signatures via mangled name comparison.

Parameters
nodeThe SgNode to be inspected, which is expected to be an SgFunctionDeclaration.
functionTypeThe SgFunctionType against which the function declaration's type will be compared.
Returns
A Rose_STL_Container containing the matching SgFunctionDeclaration if a match is found, otherwise an empty container.
Precondition
functionType must not be null.
node must be an instance of SgFunctionDeclaration.
The identified SgFunctionDeclaration must not be a template function declaration.
The first non-defining declaration of the function must not be a template function declaration.
Postcondition
If a match is found, the returned container contains the non-defining declaration.
Note
The implementation relies on the ROSE AST normalization, which ensures that a non-defining function declaration exists for every function.
The comparison is performed using the string representation of the mangled names obtained via get_mangled().getString().
