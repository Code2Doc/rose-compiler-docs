◆ compileInternalFunctionName()

std::string VxUtilFuncs::compileInternalFunctionName ( const SgFunctionDeclaration * sgFunctionDeclaration,
std::string filename )

We represent file scope functions by slapping the filename on the front of the function name.

Generates a compiled internal name for a function declaration.

Normally the internal function name is just the VxUtilFuncs::getExpandedFunctionName. However, if a function has file scope (C static or C++ anonymous namespace), such a function may collide with another file scoped function with the same name in the a different function., SO, we slap the filename on the front of the name of the function. Luckily, in a file scope function, we always have the filename, because they can only be called from the function they are defined in.

This function constructs a string representation of a function's internal name. If the function declaration is within a file scope, the provided filename is prepended to the expanded function name, separated by a space. Otherwise, it returns only the expanded function name. The expansion logic is handled by the getExpandedFunctionName utility.

Parameters
sgFunctionDeclarationA pointer to the SgFunctionDeclaration object representing the function to be named.
filenameA string containing the filename to be used as a prefix if the function is in file scope.
Returns
A string representing the compiled internal function name.
Precondition
sgFunctionDeclaration should not be a null pointer.
Postcondition
The returned string will either be "filename expandedName" or just "expandedName" depending on the scope of the declaration.

extractPriorityValue

Searches from SgNode down until it can find an SgIntVal to extract a value from. The SgIntVal is returned.

The first SgIntVal node encountered during the traversal is returned.

Generates a formatted string representing the access path or name of a given initialized name.

This function attempts to insert a node into a read or writeset or a message explaining why it can't. This can be quite a fraught process.

Parameters
[in]funcDefThe function definition the read/write was found in. Mostly used for scope info
[in]currentThe node given as a read or write. Not always sensible.

This function constructs a specialized string identifier for an SgInitializedName based on its hierarchical scope and type. The implementation traverses the AST (Abstract Syntax Tree) to determine if the node resides in a global scope, a namespace, a class definition, or within a function scope (such as local variables or parameters).

The formatting logic follows these rules:

  • For global or namespace scopes:
    • If the declaration is at file scope, it returns the node-relative path combined with the unparsed name.
    • If the type is a class type, it returns the name prefixed with '::'.
    • Otherwise, it returns the qualified name string.
  • For class definitions:
    • It returns the class name and the unparsed name delimited by '$' characters (e.g., $ClassName$VariableName).
  • For function scopes (local variables/parameters):
    • It attempts to find the parent function declaration.
    • If found, it returns the expanded function name and the variable name/qualified name delimited by '@' characters.
    • If the scope cannot be identified, it returns an error string starting with '!access unknown scope!'.
Parameters
coarseNameA pointer to the SgInitializedName node whose access string is to be generated.
Returns
A std::string containing the formatted access name, path, or an error message if the scope is unknown.
Precondition
coarseName must not be null.
The type associated with coarseName must be valid (checked via ROSE_ASSERT).
Postcondition
The function returns a string representing the hierarchical identity of the input node.
Note
The function uses ROSE-specific utility functions such as isSgGlobal, isSgClassType, and isSgClassDefinition to perform scope analysis.
If the function reaches an unreachable end state, it logs an error to mlog and calls ROSE_ABORT().
