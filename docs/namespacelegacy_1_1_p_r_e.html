void legacy::PRE::addEdgeInsertionPoints ( ControlFlowGraph & controlflow)

Determines and sets the appropriate insertion points for edges within a Control Flow Graph.

Add information to each edge on where to insert statements on that edge. The insertion point structure is a pair of (SgNode*, bool), where the bool is true for inserting before the given node and false for inserting after it.

This function iterates through all vertices and edges in the provided Control Flow Graph (CFG) to identify the precise SgStatement locations where new edges should be inserted. It analyzes the structure of the statements within each vertex (such as if-statements, while-loops, and for-loops) and the type of edges (true/false branches) to calculate an insertion point consisting of a statement pointer and a boolean flag indicating whether to insert before or after.

The implementation uses a traversal of the graph's vertices and edges. For each vertex, it examines the sequence of SgNodes to find a suitable parent statement or expression. It specifically handles various control flow constructs like V_SgDoWhileStmt, V_SgIfStmt, V_SgWhileStmt, and V_SgForStatement, adjusting the insertion point based on whether the edge represents a conditional true or false path. It also includes a fallback mechanism to ensure edges have a valid insertion point by defaulting to the last statement of a source vertex if no specific point was determined.

Parameters
controlflowA reference to a PRE::ControlFlowGraph object which is modified in-place to populate its edge_insertion_point map.
Precondition
The controlflow object must have a valid graph structure with initialized vertices and edges.
Postcondition
The controlflow.edge_insertion_pattern map is updated with valid SgStatement pointers and boolean flags for the edges in the graph.
Note
The function uses ROSE_ASSERT to validate the integrity of the SgNode pointers and the existence of parent statements during traversal.
The function handles the complexity of nested control structures by potentially recursively searching for ancestors via the try_next_ancestor label.

Get the function definition containing a given node.

Retrieves the function definition that contains the specified node.

This function performs an upward traversal of the Abstract Syntax Tree (AST) starting from the provided node n. It iteratively moves to the parent of the current node using the get_parent() method until it encounters a node that satisfies the isSgFunctionDefinition predicate.

Parameters

Returns
A pointer to the SgFunctionDefinition containing the node n. Returns 0 (nullptr) if the traversal fails, though the implementation contains an assertion to prevent this.
Precondition
The input node n must not be null.
Postcondition
The function returns a valid SgFunctionDefinition pointer if the node is part of a function scope, or the program terminates via assertion if a null parent is reached before finding a definition.
Note
The function relies on the isSgFunctionDefinition helper and the get_parent method of the SgNode class.

void legacy::PRE::partialRedundancyEliminationFunction ( SgFunctionDefinition * n)

Performs partial redundancy elimination on a given function definition.

Do partial redundancy for all expressions within a given function, whose definition is given in n.

This function implements the Partial Redundancy Elimination (PRE) optimization pass on the provided function definition. The process begins by applying constant folding to simplify the AST and remove redundant constant expression trees. It then identifies all unique expressions within the function using a FindExpressionsVisitor. For each unique expression, a Control Flow Graph (CFG) is constructed, and insertion points are added to the edges of the CFG to facilitate the elimination of partial redundancies. Finally, the partialRedundancyEliminationOne algorithm is invoked to perform the actual optimization.

Parameters
nA pointer to the SgFunctionDefinition representing the function to be optimized.
Precondition
The parameter n must be a valid, non-null pointer to an SgFunctionDefinition.
Postcondition
The function definition n is modified such that partial redundancies within its expressions have been eliminated, and the AST is simplified via constant folding.
Note
This implementation relies on the construction of a CFG and the identification of unique expressions via postorder traversal.
The function utilizes if blocks for conditional debugging code related to DOT file generation.

SgBasicBlock * root,
const myControlFlowGraph & cfg )

Performs partial redundancy elimination on a specific expression within a control flow graph.

Do partial redundancy elimination, looking for copies of one expression expr within the basic block root. A control flow graph for root must be provided in cfg, with a map from nodes to their statements in node_statements, a map from edges to their CFG edge types in edge_type, and a map from edges to their insertion points in edge_insertion_point. The algorithm used is that of Paleri, Srikant, and Shankar ("Partial redundancy elimination: a simple, pragmatic, and provably correct algorithm", Science of Computer Programming 48 (2003) 1–20).

This function implements a version of the Partial Redundancy Elimination (PRE) algorithm. It identifies computations of a given expression that are redundant on some paths but not others, and optimizes the code by inserting computations on edges to make the expression fully redundant. The implementation uses data-flow analysis (specifically fixed-point iterations for availability and anticipatability) to determine where computations can be safely moved or replaced.

The algorithm performs the following steps:

  1. Validates that the expression is not modified by its own arguments (idempotency check).
  2. Filters out simple or non-transformable expression types (e.g., variable references, function calls).
  3. Computes local properties for each basic block, including transparency, local availability, and local anticipatability.
  4. Executes fixed-point iterations to compute global availability (avin, avout) and anticipatability (antin, antout) properties across the CFG.
  5. Identifies necessary insertions of computations on edges and replacements of existing computations with a newly created cache variable.
  6. Manages the creation of a cache variable (e.g., cachevar__<counter>) and updates the AST by inserting assignment operations and replacing original expressions.
Parameters
exprThe SgExpression to be analyzed and optimized for redundancy.
rootThe SgBasicBlock representing the root or scope where the cache variable declaration will be inserted.
cfgThe control flow graph (myControlFlowGraph) representing the structure of the function being analyzed.
Precondition
expr must not be NULL.
root must not be NULL.
The expression expr should be idempotent (not modified by its own arguments).
Postcondition
If redundancy is found, the AST is modified to include a new variable declaration at the start of root and updated assignments/replacements within the CFG.
Note
The function uses include and define style logic for preprocessor-dependent code blocks.
The function may generate a new variable name using SageInterface::gensym_counter.
If an insertion point cannot be found for an edge, the function will trigger a ROSE_ABORT().

Print out a CFG as a dot file.

Exports a Control Flow Graph to a DOT format string for visualization.

This function iterates through the vertices and edges of a provided Control Flow Graph (CFG) to generate a Graphviz DOT representation. For each vertex, it aggregates the associated SgNode statements into a single record-shaped node label, including information about expression parents where applicable. The function also iterates through all edges, assigning colors based on the edge type (e.g., green for true branches, red for false) and labeling edges with insertion point information if available. Special characters such as '<', '>', and '"' are escaped to ensure the resulting DOT file is syntactically valid.

Parameters
dotfileThe output stream where the DOT formatted graph will be written.
controlflowThe Control Flow Graph structure containing vertices, edges, node statements, and edge metadata to be visualized.
Precondition
The dotfile stream must be open and writable.
Postcondition
The dotfile stream will contain a valid Graphviz 'digraph' definition representing the provided controlflow.
Note
The function uses record-shaped nodes in Graphviz to represent the internal structure of the CFG nodes.
