Rose_STL_Container< std::string > Rose::Cmdline::Java::ExpandArglist ( const std::string & arglist_string)

Expands a command-line argument string containing a filename reference.

This function processes a string that starts with an '@' symbol, which indicates that the subsequent characters represent a filename. The function extracts the filename from the string and then uses GetListFromFile to retrieve a list of arguments from that specified file. This allows for large argument lists to be stored in external files rather than passed directly on the command line.

Parameters
arglist_stringA string representing the argument list reference, which must start with the '@' character followed by a filename.
Returns
A Rose_STL_Container of strings containing the expanded list of arguments retrieved from the file.
Precondition
The input arglist_string must not be empty and must start with the '@' character.
The filename extracted from the string (the substring after the '@') must not be empty.
Postcondition
Returns a container of strings parsed from the file specified in the input string.
Warning
If the arglist_string contains only the '@' symbol without a filename, the function prints a fatal error message and calls ROSE_ABORT().
The function relies on the validity of the file path provided in the arglist_string; if the file cannot be read, the behavior depends on the implementation of GetListFromFile.
Note
The function uses ROSE_ASSERT to validate the input format during development.
If SgProject::get_verbose() is greater than 2, an informational message is printed to stdout showing the expansion details.

During the reading process, all double quote characters ('"') are stripped from each line to facilitate compatibility with certain argument file formats (e.g., Maven's javac @argfiles).

Parameters

Returns
A vector of strings containing the contents of the file, with all double quotes removed from each line.
Warning

Postcondition

See Setting the Class Path for more details.

If the -sourcepath option is not specified, the user class path is also searched for source files.

If the -processorpath option is not specified, the class path is also searched for annotation processors.

This function scans the provided command-line arguments for various Java-specific classpath flags, including -rose:java:classpath, -rose:java:cp, -classpath, and -cp. If a classpath option is found, the function extracts the associated path string, tokenizes it using the ':' delimiter, and updates the provided SgProject object with the resulting list of paths. Additionally, it performs a sanity check to verify the existence of each path on the filesystem, issuing a warning via mlog if any specified path does not exist.

Parameters
projectA pointer to the SgProject instance where the parsed Java classpath will be stored.
argvA reference to a vector of strings containing the command-line arguments to be processed. Note that identified classpath options are removed from this vector during processing.
Precondition
project must not be a null pointer.
Postcondition
If a classpath option is found, the project's Java classpath is updated and the corresponding arguments are removed from argv.
Note
The function uses Cmdline::REMOVE_OPTION_FROM_ARGV to modify the input argv vector in-place.
Path existence validation is performed using boost::filesystem::exists.

void Rose::Cmdline::Java::StripRoseOptions ( std::vector< std::string > & argv)

Removes ROSE-specific Java command-line options from the argument vector.

This function processes a vector of command-line arguments to strip out options prefixed with ROSE-specific identifiers (such as "-rose:"). It identifies options that do not require arguments and those that do, specifically targeting Java-related flags. The function utilizes CommandlineProcessing::generateOptionWithNameParameterList to parse and reformat the arguments, effectively separating ROSE-Java prefixed options from standard Java options.

The implementation follows a two-step process:

  1. It identifies and handles ROSE-specific options that do not take arguments.
  2. It processes options that include arguments, stripping the ROSE-Java prefix and preparing them for standard Java execution.
  3. It iterates through the newly generated Java options and appends them back to the original argv vector, while explicitly skipping ROSE-specific Java options like "-ds" (source/destination directory) to prevent passing ROSE-only logic to the Java runtime.
Parameters
argvA reference to a vector of strings representing the command-line arguments. This vector is modified in-place.
Precondition
The argv vector should contain valid command-line arguments.
Postcondition
The argv vector will be modified such that ROSE-specific Java prefixes are removed, and the remaining arguments are formatted as standard Java options, excluding ROSE-specific Java flags like "-ds".
Note
The function relies on Cmdline::Java::Ecj::StripRoseOptions for initial processing of certain argument types.
Warning
The logic for skipping the argument following the "-ds" flag is currently implemented with a TODO note regarding argument verification.
