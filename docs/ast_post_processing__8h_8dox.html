void AstPostProcessing ( SgNode * node)

Performs post-processing operations on an Abstract Syntax Tree (AST) node or hierarchy.

This function executes various post-processing tasks on the provided SgNode. It handles different node types such as SgProject, SgFile, and SgSourceFile. The function is designed to perform fixups and updates to the AST after parsing is complete. It also manages the clearing of the global mangled name map to ensure consistency during the post-processing phase.

The implementation uses a switch statement based on the node's variant type. For SgProject and SgFile/SgSourceFile, it invokes postProcessingSupport if the parser is not set to exit immediately after parsing. It also includes logic to warn if the function is called on a node other than an SgProject, as calling it on smaller scopes can lead to performance degradation due to repeated memory pool traversals.

Parameters
nodeA pointer to the SgNode that serves as the root or target for the post-processing operations.
Precondition
node must not be NULL.
Postcondition
The global mangled name map (SgNode::get_globalMangledNameMap()) is cleared.
Note
If the node is an SgDirectory, the function will trigger a ROSE_ABORT.
If the node is an SgBinaryComposite and ROSE_ENABLE_BINARY_ANALYSIS is defined, the function will trigger a ROSE_ABORT.
Calling this function on nodes other than SgProject may result in quadratic performance overhead.

void postProcessingSupport ( SgNode * node)

Performs AST post-processing tasks to ensure consistency and correctness of the IR.

This function executes a series of complex fixup operations on an Abstract Syntax Tree (AST) node. The primary purpose is to resolve inconsistencies introduced during the initial translation phase (e.g., from EDG or other frontends). The function handles tasks such as resetting parent pointers, fixing up symbol tables, managing template instantiations, resolving defining and non-defining declarations, and ensuring source position consistency. The logic varies depending on whether the node represents a C/C++ translation or other supported languages like Fortran, Ada, or Python.

Parameters
nodeThe root node of the AST subtree (e.g., SgProject, SgFile, or SgSourceFile) to be processed.
Precondition
The node parameter must not be NULL.
Postcondition
The AST subtree rooted at node is updated with consistent parent pointers, resolved symbol tables, and corrected declaration/instantiation metadata.
Note
The function's behavior is highly dependent on the language detected via SageInterface. For C/C++, it performs extensive fixups including template specialization marking and constant folding resets.
For non-C/C++ languages, the function performs a more limited set of operations, such as fixing up null pointers and template declarations.
The function may trigger warnings via mprintf if global scopes are found to be empty in certain file types.
Warning
Calling this function with an SgProject or SgDirectory node is historically sensitive, though recent updates have relaxed some assertions regarding these node types.
The function performs heavy-duty traversals and computations that can be computationally expensive on large ASTs.
