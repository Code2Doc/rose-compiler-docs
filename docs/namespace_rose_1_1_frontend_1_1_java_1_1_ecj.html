void Rose::Frontend::Java::Ecj::jserver_start ( JvmT * je)

Initializes and starts the Java Virtual Machine (JVM) within a JvmT context.

This function configures the necessary arguments for JVM initialization, including setting the JNI version to 1.6 and handling unrecognized options. It retrieves JVM options from the Rose::Cmdline::Java::Ecj namespace, appends the Rose classpath, and explicitly sets the thread stack size to 2MB (-Xss2m) to prevent crashes on certain Linux distributions like RHEL7. The function iterates through the list of options, allocates memory for each option string using strdup, and populates the JavaVMInitArgs structure. Finally, it invokes JNI_CreateJavaVM to instantiate the VM.

Parameters
jeA pointer to a JvmT structure which holds the resulting JavaVM and JNIEnv handles upon successful initialization.
Warning
If the JVM fails to initialize (indicated by a negative return value from JNI_CreateJavaVM or null pointers for the JVM or Env), the function will call exit(1), terminating the entire process.
Precondition
The pointer je must be a valid, non-null pointer to an allocated JvmT object.
The global configuration Rose::Cmdline::Java::Ecj::jvm_options must be accessible.
Postcondition
If successful, the je->jvm and je->env members of the provided JvmT structure will be populated with valid handles to the newly created Java Virtual Machine.
Note
This function uses strdup to duplicate option strings; ensure that the lifecycle of these strings is managed according to JNI requirements.
The stack size is hardcoded to -Xss2m to improve stability on specific operating system environments.
