std::vector< int > breakTriple ( std::vector< SgGraphNode * > expr)

Identifies the boundary indices within a vector of SgGraphNode pointers based on a matching index node.

This function iterates through a vector of SgGraphNode pointers to find the position where the underlying SgNode of the first element in the vector reappears. It identifies three specific boundary points: the start of the vector, the index of the first recurrence of the initial SgNode, and the final index of the vector.

Parameters
exprA vector of pointers to SgGraphNode objects to be scanned. The first element (expr[0]) serves as the reference for the search.
Returns
A std::vector<int> containing exactly three integer values representing the identified bounds:
  • bounds[0]: Always 0.
  • bounds[1]: The index of the first element in the vector whose SgNode matches the SgNode of expr[0] (excluding the first element itself).
  • bounds[2]: The index of the last element in the vector (expr.size() - 1).
Precondition
The input vector expr must not be empty.
The element expr[0] must not be null so that get_SgNode() can be called.
The SgNode of expr[0] must exist within the sequence of SgNodes in the expr vector at some index i > 0 to prevent an infinite loop or out-of-bounds access.
Postcondition
The returned vector contains exactly three elements.
Warning
If the SgNode of expr[0] is not found again in the subsequent elements of expr, the function will continue to increment the index i until it exceeds the bounds of the vector, potentially leading to undefined behavior or a ROSE_ASSERT failure.
Note
The implementation relies on the get_SgNode() method of the SgGraphNode class.

It traverses the provided path, interpreting various C++ constructs such as return statements, variable initializations, while loops, for loops, and if statements. The function uses the YICES SMT solver to maintain and assert constraints (path conditions) encountered during the traversal. It handles loop unrolling up to a defined constant (FORLOOPS) and manages the creation of fresh YICES variables for new assignments.

Parameters

ctxA reference to the YICES context used for managing SMT expressions, assertions, and solver state.
mainFlagA boolean flag indicating whether the function is executing in the main context or as a sub-evaluation (e.g., evaluating a branch or loop body).
Returns
A yices_expr representing the result of the evaluated path (e.g., a return value or a fresh boolean variable if an inconsistency is detected).
Precondition
The yices_context ctx must be valid and initialized.
The path vector should contain valid SgGraphNode pointers.
Postcondition
The YICES context ctx may contain new assertions and variables corresponding to the logic found in the path.
If an inconsistency is detected in the solver during traversal, a fresh boolean variable is returned.

Performs interprocedural path analysis and control flow graph construction for a given project.

This function serves as a driver for a static analysis tool. It initializes the analysis environment, loads a project using a frontend, and iterates through all function definitions within the project. For each function, it constructs an Interprocedural Control Flow Graph (ICFG) and utilizes a path analyzer to identify and map execution paths. It specifically handles the instantiation of graphs and the execution of a visitor pattern to traverse the program structure.

Parameters
argcThe number of command-line arguments.
argvAn array of character pointers representing the command-line arguments.
Returns
An integer status code, where 0 indicates successful completion of the analysis.
Precondition
The project files provided via argv must be valid and accessible by the frontend function.
The SageInterface::findMain function must be able to locate a valid main function within the loaded project.
Postcondition
A mapping of function definitions to their discovered execution paths is stored in FuncPathMap.
The analysis results and path counts are printed to the standard output.
Note
The function relies on the ROSE compiler infrastructure for AST and CFG manipulation.
The function uses a visitorTraversalFunc to perform path analysis on individual functions.
The function uses a visitorTraversal to perform analysis on the main function definition.
