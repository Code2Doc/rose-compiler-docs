void find_ada_files ( std::string dir,
std::vector< std::string > & ada_files )

Searches a directory for Ada source files and populates a vector with their paths.

This function iterates through the contents of the specified directory using a directory iterator. It inspects each entry to determine if it is a regular file and checks if the file extension matches the Ada source file patterns, specifically ".adb" (Ada body) or ".ads" (Ada specification). Any matching file paths found are appended to the provided vector.

Parameters
dirA string representing the path to the directory to be searched.
ada_filesA reference to a vector of strings where the paths of discovered Ada files will be stored.
Precondition
The directory path provided in dir must exist and be accessible by the current process.
Postcondition
The ada_files vector will contain the full paths of all files ending in .adb or .ads found within the specified directory. Note that existing elements in ada_files are preserved.
Note
This function only searches the top-level directory provided and does not perform a recursive search into subdirectories.
The implementation relies on the boostfs library for filesystem operations and directory iteration.

void find_additional_compilation_units ( ada_base_entity * lal_root,
ada_analysis_context & ctx,
std::vector< ada_base_entity > & comp_units_storage )

Scans an Ada compilation unit for dependencies and recursively discovers related compilation units.

This function performs a deep traversal of the Ada dependency graph starting from a root compilation unit. It identifies additional compilation units to be analyzed by inspecting three specific areas:

  1. The fully qualified name of the current unit (checking for parent units in a hierarchical package structure).
  2. The 'with' clauses in the prelude of the current unit (identifying imported packages).
  3. The body of the current unit (checking if the unit is a subunit of a parent package).

For each identified dependency, the function attempts to resolve both the specification (.ads) and the body (.adb) versions, unless the package belongs to a system namespace (e.g., starting with 'ada.', 'gnat.', or 'system.'). The function uses a recursive approach to ensure that all transitive dependencies are discovered and added to the storage vector.

Parameters
lal_rootA pointer to the root Ada base entity representing the compilation unit currently being inspected.
ctxThe Ada analysis context used to provide and resolve analysis units.
comp_units_storageA vector of Ada base entities used to store the discovered compilation units. This vector is updated in-place as new units are found.
Precondition
The lal_root pointer must be a valid, non-null pointer to an ada_base_entity.
The ctx reference must be a valid, initialized ada_analysis_context.
Postcondition
The comp_units_storage vector will contain the lal_root's dependencies, including any transitive dependencies found during the recursive traversal.
Note
The function logs diagnostics and information messages to the Libadalang_ROSE_Translation::mlog stream.
If a unit is found to have diagnostics (errors/warnings) during initialization, the function logs the diagnostic details and skips adding that unit to the storage.

int libadalang_main ( const std::vector< std::string > & args,
SgSourceFile * file )

Orchestrates the translation of Ada source files to ROSE Sg format using Libadalang.

This function serves as the main entry point for the Libadalang-to-ROSE translation process. It initializes the ROSE environment, parses command-line arguments to configure GNAT and ASIS compiler flags, and locates necessary Ada source files and system include directories. The function sets up an Ada analysis context, identifies all relevant compilation units (including dependencies and specification files), and invokes the translation engine. It handles the complexities of GNAT environment variables, such as include% GNAT_HOME, and manages the discovery of Ada library files.

Parameters
argsA vector of strings containing command-line arguments, used to extract include paths (via -I) and GNAT-specific compiler options.
fileA pointer to the SgSourceFile object representing the primary Ada source file to be processed.
Returns
An integer status code where 0 indicates successful translation and 1 indicates a failure (e.g., missing GNAT_HOME, translation error, or unhandled exception).
Precondition
The environment variable GNAT_HOME must be set and point to a valid GNAT installation.
Postcondition
The input Ada source file (and its dependencies) is translated into the ROSE Sg representation, provided no fatal errors occurred. The global ROSE assertion behavior is restored to its original state.
Warning
If GNAT_HOME is not found in the environment, the function will log a fatal error and return 1.
Note
The function performs recursive discovery of Ada files in the source directory and system include paths. It also handles the conversion of file path naming conventions (e.g., replacing '-' with '.') when locating corresponding Ada specification (.ads) files for body (.adb) files.
