size_t checkIsFrontendSpecificFlag ( SgNode * ast)

Identifies and counts violations where frontend-specific file information is not correctly marked.

Checks whether appropriate nodes of an AST are marked as front-end specific.

A node is frontend-specific if it was parsed from the "rose_edg_required_macros_and_functions.h" or if it has an ancestor in the AST that is frontend-specific. All violations are fixed in place. Returns the number of violations found/fixed.

Identifies and counts violations where frontend-specific nodes are not correctly marked.

This function traverses the provided Abstract Syntax Tree (AST) to detect nodes that belong to a frontend-specific context but lack the appropriate frontend-specific flag in their file information. It uses an internal visitor structure, T1, which implements a pre-order and post-order traversal strategy.

During the pre-order traversal, the function checks if a node or its associated location information (start/end of construct, file info, etc.) belongs to a frontend-specific header, specifically checking for the presence of "/rose_edg_required_macros_and_functions.h". If a node is identified as being within a frontend-specific AST, the function ensures that all associated file information objects are marked as frontend-specific. If a file information object is found to be part of a frontend-specific context but is not yet marked as such, it is updated, and a violation counter is incremented. The post-order traversal is used to reset the tracking of the frontend-specific AST root once the traversal exits that subtree.
