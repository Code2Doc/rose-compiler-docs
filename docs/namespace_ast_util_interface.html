std::pair< std::string, std::string > AstUtilInterface::AddOperatorSideEffectAnnotation ( SgNode * op_ast,
const AstNodePtr & var,
OperatorSideEffect relation )

Annotates an operator node with side-effect information regarding a specific variable.

Record that op_ast references the given variable with the given relation: (modify, read, or call). Returns the string representation of the operator and variable.

This function identifies the side-effect relationship (such as Modify, Read, or Call) between a given operator AST node and a variable. It retrieves the variable's signature and updates the corresponding side-effect descriptor within the global OperatorSideEffectAnnotation instance. The function uses an internal AST interface implementation to traverse the operator node and determine its properties. If the variable name is unknown or empty, it marks the descriptor as having an unknown side effect; otherwise, it pushes a symbolic value descriptor into the descriptor.

Parameters
op_astA pointer to the SgNode representing the operator in the AST.
varA pointer to the AstNode representing the variable involved in the side effect.
relationAn enum value of type OperatorSideEffect indicating the nature of the relationship (e.g., Modify, Read, Call, etc.).
Returns
A pair of strings where the first element is the variable signature of the operator node (op_ast) and the second element is the signature of the provided variable (var). Returns a pair of empty strings if the op_ast is not a valid function definition.
Precondition
op_ast should be a valid pointer to an SgNode that represents an operator or function definition.
Postcondition
The OperatorSideEffectAnnotation instance is updated with the side-effect relationship between the operator and the variable, provided the relation is supported and the descriptor is successfully retrieved.
Note
If the relation is one of the non-descriptor types (Kill, Decl, Allocate, Free), no descriptor update is performed.
Warning
If the relation type is not recognized in the switch statement, the function will trigger an assertion failure.
If the op_ast cannot be identified as a function definition, the function returns an empty pair and logs a debug message.

Overloads the stream insertion operator for the DependenceEntry class.

This function provides a formatted string representation of a DependenceEntry object for output to an output stream. The output format includes the first entry, the type entry enclosed in brackets, and the second entry. If an attribute entry exists, the function appends a specific delimiter based on the type of dependence: " <- " for "modify" types, " -> " for "read" types, and " = " for all other types. Every entry is terminated with a semicolon.

Parameters
outputThe output stream where the formatted dependence information will be written.
eThe DependenceEntry object to be serialized into the stream.
Returns
A reference to the modified output stream to allow for chained stream operations.
Precondition
The DependenceEntry object e must be in a valid state such that its member functions first_entry(), type_entry(), second_entry(), and attr_entry() can be called without undefined behavior.
Postcondition
The output stream output will contain the string representation of the dependence entry, ending with a semicolon.
Note
The formatting logic relies on the string values returned by type_entry(). Specifically, it checks for the exact string literals "modify" and "read".

If the pointer is null, the function retrieves the singleton instance of OperatorSideEffectAnnotation and writes its contents directly to the output stream.

Reads annotation data from an input stream into the specified analysis object or global singleton.

Read annotation from the given file. The annotations will be stored internally to be used later to assist program analysis within the compiler. Only annotations supported by those already registered can be parsed correctly. Use the given dependence analysis if it is not 0.

This function handles the ingestion of annotation information from a provided input stream. The implementation branches based on the availability of a dependence analysis object. If a pointer to a WholeProgramDependenceAnalysis object is provided, the function invokes the CollectPastResults method on that object to process the stream. Otherwise, it falls back to using the singleton instance of ReadAnnotation to read from the stream.

Parameters
inputA reference to a std::istream from which the annotation data is read.
use_dep_analysisA pointer to a WholeProgramDependenceAnalysis object. If this pointer is non-null, the function uses this object to collect results. If null, the function uses the ReadAnnotation singleton.
Precondition
The input stream must be in a valid state and positioned at the start of the annotation data to be read.
Postcondition
The state of the input stream will be advanced by the number of bytes read. The internal state of use_dep_analysis (if provided) or the ReadAnnotation singleton will be updated with the parsed annotations.
Note
If use_dep_analysis is null, the function relies on the global state of the ReadAnnotation::get_inst() singleton.
