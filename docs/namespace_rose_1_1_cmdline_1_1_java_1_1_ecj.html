ROSE_DLL_API std::string Rose::Cmdline::Java::Ecj::GetRoseClasspath ( )

Constructs the Java classpath string for the ECJ front-end.

This function builds a formatted string suitable for the -Djava.class.path Java system property. It determines the appropriate path separator based on the operating system (using a semicolon for MSVC environments and a colon otherwise). The function specifically appends paths for the ECJ jar file and its associated source tree directory by resolving their locations relative to the build tree using findRoseSupportPathFromBuild. Finally, it appends the current directory to the classpath.

Precondition
The function relies on findRoseSupportPathFromBuild being correctly defined and accessible in the current scope.
Postcondition
Returns a string containing the formatted classpath starting with "-Djava.class.path=" and containing all necessary library paths separated by the platform-specific delimiter.
Note
The implementation uses ifdef _MSC_VER to handle platform-specific path separators.
Returns
A std::string representing the complete Java classpath configuration.

Enables remote debugging for the Java ECJ process if the appropriate command-line option is present.

-rose:java:ecj:enable_remote_debugging Enable remote debugging of the Java Virtual Machine (JVM).

This function scans the provided command-line arguments for the specific option -rose:java:remoteDebug. If this option is found, the function attempts to append the necessary JDWP agent configuration to the global jvm_options vector to allow for remote debugging via a socket on port 8000. The function also removes the processed option from the argv vector to prevent it from being passed downstream.

Parameters
projectA pointer to the SgProject instance. Used to check the verbosity level of the project for logging purposes.
argvA reference to a vector of strings containing the command-line arguments. The function searches for the remote debugging flag and modifies this vector by removing the flag if it is found.
Precondition
The argv vector must be a valid, modifiable vector of strings.
Postcondition
If the -rose:java:remoteDebug option is found in argv, it is removed from the vector. If ifdef ROSE_BUILD_JAVA_LANGUAGE_SUPPORT is defined, the JDWP agent string is appended to Cmdline::Java::Ecj::jvm_options.
Warning
If the -rose:java:remoteDebug option is detected but the ROSE_BUILD_JAVA_LANGUAGE_SUPPORT macro is not defined, the function will print a fatal error message and call ROSE_ABORT(), terminating the program.
Note
The function relies on CommandlineProcessing::isOption to identify the presence of the specific Java option prefix and name.

ROSE_DLL_API void Rose::Cmdline::Java::Ecj::StripRoseOptions ( std::vector< std::string > & argv)

Removes ROSE-specific Java ECJ command-line options from the argument vector.

This function processes the command-line argument vector to identify and strip out options that are specific to the ROSE Java ECJ (Eclipse Compiler for Java) integration. It handles two types of options: those without arguments and those with arguments. The function utilizes sla to handle flag-style options and CommandlineProcessing::generateOptionWithNameParameterList to extract and transform options prefixed with -rose:java:ecj:.

The implementation specifically targets the removal of options that are intended only for the ECJ frontend's JVM, ensuring that the remaining argv contains only the necessary arguments for the subsequent compilation stages.

Parameters
argvA reference to a vector of strings representing the command-line arguments. This vector is modified in-place by removing the identified ROSE-specific options.
Precondition
The argv vector should contain the raw command-line arguments passed to the application.
Postcondition
The argv vector will no longer contain any arguments starting with the -rose:java:ecj: prefix or the -ecj: prefix after processing.
Note
If SgProject::get_verbose() is greater than 1, the function will print informational messages to std::cout regarding the stripping process.
