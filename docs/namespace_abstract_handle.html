Detailed Description

Auto-generated documentation for the AbstractHandle namespace.

String annotations to uniquely indicate any source constructs.

A reference implementation of abstract handles for language constructs Used for specifying a unique language construct in source files.

Users are required to implement the interface using their own IR node types.

Goal : Only define interfaces and abstract implementation independent to any particular compilers or tools

We provide ROSE's implementation.

Essentially, you can use a string to uniquely specify any language constructs in your source code and convert the string to AST node.

This is useful to pass string options to translators so they can operate on the desired language constructs (e.g. for loops)

Example use in outliner: outline the for loop at line 12 of the input code ./outline -rose:outline:abstract_handle "ForStatement<position,12>" -c inputCode_OutlineLoop2.c Outline the 2nd for statement of the input code

./outline -rose:outline:abstract_handle "FunctionDeclaration<name,initialize>::ForStatement<numbering,2>" -c inputCode_OutlineLoop2.c Outline the statement at line 5 of the input code ./outline -rose:outline:abstract_handle "Statement<position,5>" -c declarations.c

ROSE_DLL_API abstract_handle * AbstractHandle::buildAbstractHandle ( SgNode * snode)

A default builder function handles all details: file use name, others use numbering.

Generates a hierarchical chain of abstract handles for a given SgNode.

This function constructs a complete abstract handle for a specific node by tracing its scope hierarchy back to the global scope. For simple top-level nodes (such as SgSourceFile, SgProject, or SgGlobal), it performs a single handle generation. For all other nodes, the function traverses upwards through the enclosing scopes using SageInterface::getEnclosingScope, collecting all intermediate scope nodes in a list. It then iterates through this list in reverse order (from the global scope downwards to the node's immediate parent) to incrementally build the handle chain, finally appending the handle for the target node.

Parameters
snodeThe SgNode for which the abstract handle is to be generated.
Returns
A pointer to the fully constructed abstract_handle representing the node and its ancestry. Returns a non-null pointer.
Precondition
snode must not be NULL.
Postcondition
The returned abstract_handle represents the hierarchical path from the global scope down to the provided snode.
Note
The function relies on the existence of a valid scope hierarchy leading back to an SgGlobal node.
The implementation uses a vector to store intermediate nodes and a reverse iterator to process the hierarchy from the root downwards.

ROSE_DLL_API roseNode * AbstractHandle::buildroseNode ( SgNode * snode)

A builder function to avoid duplicated building.

Retrieves or creates a roseNode associated with a given SgNode.

This function implements a factory pattern with memoization to ensure that each SgNode is mapped to exactly one roseNode instance. It maintains a static std::map that tracks the relationship between SgNode pointers and roseNode pointers. If the provided SgNode has not been processed before, a new roseNode is instantiated, linked to the SgNode, and stored in the internal cache.

Parameters
snodeA pointer to the SgNode for which a roseNode is required.
Returns
A pointer to the roseNode associated with the input snode. The returned roseNode is guaranteed to be non-null if the function completes successfully.
Precondition
snode must not be NULL.
Postcondition
If the snode was not previously in the map, a new roseNode is allocated and the internal static map is updated.
Note
This function uses a static std::map, which means the mapping persists across multiple calls for the lifetime of the program.
The function relies on an assertion to ensure the validity of the constructed roseNode and its underlying SgNode.

abstract_handle * AbstractHandle::buildSingleAbstractHandle ( SgNode * snode,
abstract_handle * p_handle = NULL )

A helper function to build a single abstract handle item.

This function facilitates the creation and retrieval of abstract handles associated with specific ROSE AST nodes. It first attempts to retrieve an existing handle from a global cache (handle_map) using the corresponding abstract node. If no handle exists, it constructs a new one based on the type of the input SgNode. For top-level nodes such as SgSourceFile, SgProject, or SgGlobal, a default handle is created. For other node types, the function uses either the node's name (for function definitions) or a numbering scheme (for other types) relative to a provided parent handle.

Parameters
snodeA pointer to the SgNode for which the abstract handle is being built.
p_handleA pointer to the parent abstract_handle. This is used for nodes that require hierarchical naming or numbering. Defaults to NULL.
Returns
A pointer to the newly created or previously cached abstract_handle.
Precondition
snode must not be NULL.
If snode is not a SgSourceFile, SgProject, or SgGlobal, p_handle must not be NULL.
Postcondition
The resulting abstract_handle is cached in the handle_map for future retrieval.
Note
The function relies on the existence of a global or accessible handle_map and a function buildroseNode to convert SgNode to abstract_node.

ROSE_DLL_API SgLocatedNode * AbstractHandle::convertHandleToNode ( const std::string & cur_handle)

Convert an abstract handle string to a located node in AST.

Converts an abstract handle string into a corresponding located node in the AST.

This function iterates through the list of files associated with the current project to find an AST node that matches the provided abstract handle string. It constructs an abstract handle for each source file in the project, appending the provided cur_handle to the file handle, and then attempts to resolve the underlying SgNode. The process involves traversing the file list, building ROSE nodes for each source file, and performing type-safe checks to identify if the resulting node is an instance of SgLocatedNode.

Parameters
cur_handleA string representing the abstract handle path to be resolved.
Returns
A pointer to the SgLocatedNode if a matching node is found; otherwise, returns NULL if no match is found, if the project is NULL, or if the platform (e.g., ifdef _MSC_VER) prevents certain covariant type conversions.
Precondition
The function assumes that getProject() returns a valid SgProject pointer if the project exists.
Postcondition
If a node is found, the returned pointer points to a valid SgLocatedNode within the existing AST.
Note
The implementation uses ifdef _MSC_VER to handle limitations in MSVC regarding covariant return types in abstract_node::getNode().
The function relies on the existence of a valid project and file list to perform the search.

Parse a string (such as 12.10, 13, 0 etc )into source position data structure.

Parses a string representation of a source position into a source_position structure.

This function takes a string containing numerical data (e.g., "12.10", "13", or "0") and extracts the line and column information into the provided source_position object. The implementation uses an istringstream to parse the input. It first attempts to extract the line number as a decimal integer. If a dot character ('.') is detected immediately following the line number, the function then attempts to parse the subsequent value as the column number.

Parameters
posA reference to a source_position structure that will be populated with the parsed line and column values.
inputA string containing the source position data to be parsed.
Precondition
The input string should follow a format compatible with decimal integer parsing, optionally followed by a '.' and another decimal integer for the column.
Postcondition
The pos.line and pos.column members are updated based on the input string. If parsing fails, the line and column are reset to 0.
Note
If the input string is empty or the initial line number cannot be parsed, the function returns early and sets both line and column to 0.
The function is designed to be robust against malformed input by resetting the position to zero before attempting parsing.

Parses a hyphen-delimited string to populate a pair of source positions.

This function takes a string containing two parts separated by a hyphen ('-') and parses each part individually to update the first and second elements of a source_position_pair. It utilizes an istringstream to split the input string based on the '-' delimiter and then recursively calls fromString for each extracted substring.

Parameters
pos_pairA reference to a source_position_pair object that will be updated with the parsed position information.
inputA constant reference to a string containing the hyphen-separated position data (e.g., "start_pos-end_pos").
Precondition
The input string must follow the format "part1-part2", where part1 and part2 are valid strings that can be processed by the single-argument fromString function.
Postcondition
The pos_pair.first and pos_pair.second members are updated based on the parsed substrings.
Note
The function uses fixed-size buffers of 256 characters for each part. If a part exceeds 255 characters, the parsing may fail or truncate.

Parses a specifier object from a formatted string representation.

This function parses a string containing specifier information formatted as '<type,value>'. It extracts the type and value components, identifies the specifier type (such as name, position, or numbering), and populates the provided result object. The function uses an istringstream to tokenize the input string based on comma and angle bracket delimiters.

Parameters
resultA reference to a specifier object that will be populated with the parsed type and value.
inputA string containing the formatted specifier data. The string must follow the format '<type,value>'.
Precondition
The input string must not be empty.
In non-debug builds, the input string must start with the '<' character.
The input string must be correctly formatted with a comma separating the type and value, and ending with a '>'.
Postcondition
The result object is updated with the parsed specifier type and value.
Warning
If the input string is empty, an assertion failure will occur.
If the parsed type is not recognized (e.g., not "name", "position", or "numbering"), the function will print an error to stderr and call ROSE_ABORT().
For the "numbering" type, if the value cannot be parsed as a decimal integer, the function will print an error and call ROSE_ABORT().
Note
The function handles "name" by copying the string, "position" by recursively calling fromString, and "numbering" by parsing an integer.

Postcondition

bool AbstractHandle::isEqual ( const source_position & pos1,
const source_position & pos2 )

Compares two source positions for equality using inexact matching.

This function performs a comparison between two source position structures. The comparison is designed to be inexact to accommodate cases where source position information might be partial. Specifically, a dimension (line or column) is only compared if both positions provide non-zero information for that dimension. If either position has a zero value for a specific dimension, that dimension is treated as a match. This allows for compatibility between full source positions and partial positions (e.g., only a line number provided).

Parameters
pos1The first source position to compare.
pos2The second source and position to compare.
Returns
True if the non-zero components of both positions match, false otherwise.
Precondition
The input parameters pos1 and pos2 must be valid instances of source_position.
Postcondition
The return value indicates whether the provided positional information is consistent.
Note
This implementation avoids strict equality to handle scenarios where a compiler provides full source position data but the user only provides a line number.

Compares two source position pairs for equality.

This function determines whether two source position pairs are identical. The comparison logic first verifies if the line numbers of the starting positions (the first element of each pair) are equal. If the line numbers do not match, the function returns false immediately to avoid incorrect matches with empty file information. If the line numbers match, it proceeds to recursively check the equality of the underlying position components.

Parameters
pair1The first source position pair to be compared.
pair2The second source position pair to be compared.
Returns
True if both pairs represent the same source positions, false otherwise.
Precondition
The input pairs must contain valid source position data.
Postcondition
The state of the input pairs remains unchanged.
Note
The implementation relies on an overloaded isEqual function for the underlying position objects.
