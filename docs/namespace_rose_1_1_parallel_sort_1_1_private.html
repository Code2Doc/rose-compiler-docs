const Work< RandomAccessIterator > & work )

Adds a new work unit to the specified job's worklist.

This function appends a new work item to the end of the worklist associated with a given job. It ensures thread safety by acquiring a mutex lock on the job object before modifying the internal worklist. After the work is successfully added, it notifies one waiting thread via a condition variable to signal that new work is available for processing.

Parameters
jobA reference to the Job object to which the work will be added. This object must contain a mutex and a worklist.
workA constant reference to the Work unit to be appended to the job's worklist.
Precondition
The job object must be properly initialized and its mutex must be accessible.
Postcondition
The work item is appended to the job's worklist, and one thread waiting on job.worklistInsertion is notified.
Note
This function uses boost::lock_guard for RAII-style mutex management to prevent deadlocks in case of exceptions during the push_back operation.

Partitions a range into two groups based on a pivot element.

This function implements a partitioning algorithm similar to the Lomuto partition scheme. It rearranges the elements in the range [begin, end) such that all elements for which compare returns true when compared to the pivot are placed before the pivot, and all elements for which compare returns false are placed after the pivot. The function temporarily moves the pivot to the end of the range to facilitate the partitioning process and then restores it to its final position.

Parameters
beginAn iterator pointing to the start of the range to be partitioned.
endAn iterator pointing to the end of the range (one past the last element).
pivotAn iterator pointing to an element within the range [begin, end) that will be used as the pivot for partitioning.
compareA binary predicate that accepts two elements and returns true if the first element should precede the second.
Returns
An iterator pointing to the final position of the pivot element after the partitioning is complete.
Precondition
The range [begin, end) must be non-empty (begin < end).
The pivot iterator must be within the range [begin, end).
Postcondition
The range [begin, end) is partitioned such that all elements in [begin, pivot) satisfy compare(*i, *pivot) == true and all elements in (pivot, end) satisfy compare(*pivot, *i) == true (assuming a strict weak ordering).
The pivot element itself is located at the returned iterator position.
Note
This implementation uses std::swap to rearrange elements.
The complexity of this function is O(n), where n is the distance between begin and end.

Performs a parallel-ready quicksort on a range of elements.

This function implements a quicksort algorithm that utilizes a hybrid approach. It recursively partitions the range using a pivot-based partitioning scheme. To optimize performance and reduce overhead, the function checks the size of the current work range against a predefined multi-threshold within the job object. If the range size is below this threshold, the function switches to a standard sequential std::sort implementation.

Parameters
jobA reference to a Job object containing the comparison logic and the multi-threshold value used to decide when to switch to sequential sorting.
workA Work object representing the current range of elements to be sorted, defined by begin and end iterators.
Precondition
The iterators provided within the work object must satisfy the requirements of a RandomAccessIterator.
The comparison function provided in the job object must be a valid strict weak ordering comparator.
Postcondition
The elements in the range [work.begin, work.end) are sorted in non-descending order according to the comparator in job.
Note
The efficiency of the partitioning step assumes a fairly even distribution of elements around the chosen pivot.
This function may add new work units to the job object via the addWork function during the partitioning process.
