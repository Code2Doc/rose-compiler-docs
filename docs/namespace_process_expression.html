Helper Function to process Left Hand Side of an Expression.

Processes the left-hand side (LHS) of an expression to identify variable symbols and dereference levels.

This function traverses an expression tree starting from the provided node to identify the underlying variable symbol and calculate the total number of pointer dereferences applied to it. It handles various node types including initialized names, variable references, pointer dereferences, and member access operators (dot and arrow). The function recursively descends through pointer dereferences and member access operands to find the base variable.

Parameters
nodeThe starting SgNode representing the left-hand side of the expression to be analyzed.
arNodeA reference to an AliasRelationNode structure where the identified variable symbol and the accumulated dereference level will be stored.
Precondition
The node parameter must not be NULL.
Postcondition
The arNode.var member is updated with the identified SgVariableSymbol (or NULL if no valid non-pointer/non-reference variable is found), and arNode.derefLevel is updated to reflect the total number of dereference operations encountered during traversal.
Note
The function uses ROSE_ASSERT to validate that nodes are correctly cast to their expected types during the switch-case processing.
If the identified symbol is a pointer type and not a reference type, the symbol is set to NULL to ensure only direct variable access or reference access is captured in the arNode.var.

Helper Function to process Right Hand Side of an Expression.

Analyzes the right-hand side of an expression to identify the underlying variable and its dereference level.

This function recursively traverses an expression tree (SgNode) to determine which variable is being accessed and how many levels of pointer indirection (dereferencing) are involved. It handles various C++ expression types including variable references, pointer dereferences, address-of operations, member access (dot and arrow operators), assignments, casts, and dynamic memory allocation (new).

For complex cases like new expressions, the function may generate temporary variable declarations within the nearest available scope to ensure every memory location is associated with a symbolic name.

Parameters
nodeThe SgNode representing the expression to be processed.
arNodeA reference to an AliasRelationNode structure used to store the discovered variable symbol and the calculated dereference level.
Precondition
The node parameter must not be NULL.
Postcondition
The arNode.var member is updated to point to the identified SgVariableSymbol, and arNode.derefLevel is updated to reflect the total number of pointer dereferences encountered during traversal.
Note
The function uses a static map new_variables to track variables created from new expressions to maintain consistency across multiple calls.
The function relies on ROSE-specific helper functions such as isSgVarRefExp, isSgPointerDerefExp, and isSgAddressOfOp for type identification.
