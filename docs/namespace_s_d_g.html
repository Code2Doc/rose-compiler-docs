DominanceFrontiersT SDG::buildDominanceFrontiers ( const ControlFlowGraph & cfg)

Build dominance frontiers for all nodes in the given CFG.

Computes the dominance frontiers for a given Control Flow Graph.

This function calculates the dominance frontiers of all nodes within the provided Control Flow Graph (CFG). The algorithm utilizes the immediate dominator tree (IDom) and performs a bottom-up traversal of the dominator tree using a stack-based approach. For each node, it identifies edges leading to successors that are not dominated by the current node, effectively mapping control dependence relationships. The implementation relies on the dominator tree structure and processes nodes from leaves to the root to propagate dominance frontier information upwards.

Parameters
cfgThe Control Flow Graph for which the dominance frontiers are to be computed.
Returns
A mapping representing the dominance frontiers, where each node is mapped to its frontier nodes and the edges that trigger the dependence.
Warning
This function requires the input CFG to be acyclic in a way that allows dominator tree construction; if a cycle is detected via checkCycle, an exception is thrown.
Precondition
The input ControlFlowGraph cfg must be a valid, well-formed graph.
The function assumes that the immediate dominator tree can be retrieved via cfg.getDominatorTree().
Postcondition
The returned DominanceFrontiersT contains the computed dominance frontiers for all reachable nodes in the CFG.
Note
The function uses a bottom-up traversal of the dominator tree, which is achieved by first identifying all children in the tree and then processing vertices in reverse topological order.

bool SDG::filterCfgNode ( const VirtualCFG::CFGNode & cfgNode)

Determines whether a specific CFG node should be retained during the filtering process.

This function evaluates a given Control Flow Graph (CFG) node to decide if it meets the criteria for being "interesting" and should be kept in the filtered graph. The filtering logic inspects the underlying SgNode associated with the CFG node. It specifically checks for function calls, certain types of expressions (like conditional or expression list expressions), function definitions, and function parameters. It also explicitly excludes certain statement types such as break, continue, return, and various statement variants.

Parameters
cfgNodeThe CFG node to be evaluated for filtering.
Returns
True if the node meets the criteria to be kept (is interesting and passes the structural filters); false otherwise.
Precondition
The cfgNode parameter must be a valid, non-null reference to a VirtualCFG::CFGNode.
Postcondition
The state of the cfgNode is not modified.
Note
The filtering logic relies heavily on the underlying AST structure and the variant type of the SgNode.

void SDG::generateDefUseChainsFromSSA ( SgProject * project,
DefUseChains & defUseChains )

Generates Def-Use chains by analyzing Static Single Assignment (SSA) information.

This function constructs Def-Use chains by leveraging an SSA-based Control Flow Graph (CFG) analysis. The process involves two main phases:

  1. Iterating through all SgNode elements in the project to identify variable uses. For each use, the function retrieves the corresponding reaching definition from the SSA representation and maps the definition's CFG nodes to the specific variable reference.
  2. Handling function parameters passed by reference. The function identifies all SgFunctionDefinition nodes, determines which parameters are passed by reference, and checks the reaching definitions at the end of the function. If a parameter passed by reference is part of a single reaching definition, a Def-Use chain is established from its actual definitions to the parameter itself.
Parameters
projectA pointer to the SgProject containing the AST and SSA information to be analyzed.
defUseChainsA reference to a DefUseChans structure where the resulting definition-to-use mappings will be stored.
Precondition
The project must contain a valid SSA-based Control Flow Graph (SSA_UnfilteredCfg) and the SgNodes must be traversable via NodeQuery.
Postcondition
The defUseChains object is populated with mappings from CFG nodes to sets of variable references (SgVarRefExp or SgInitializedName) that are defined at those nodes.
Note
This implementation relies on the SSA_UnfilteredCfg class to provide reaching definition information and uses SageInterface queries to traverse the AST.

Constructs def-use chains based on the results of a variable renaming pass.

This function performs a data-flow analysis step to populate a def-use chain structure. It first executes a variable renaming pass on the provided SgProject to resolve variable occurrences. It then iterates through the resulting DefUseTable produced by the VariableRenaming process. For every node identified in the use table, the function maps the corresponding definition to its associated uses, effectively building the chains within the defUseChans structure.

Parameters
projectA pointer to the SgProject containing the AST nodes to be analyzed.
defUseChainsA reference to a DefUseChains object that will be populated with the computed definition-use relationships.
Precondition
The project pointer must not be null and must contain a valid, traversable AST.
Postcondition
The defUseChains object will be updated to include mappings from SgNode definitions to their respective uses as determined by the renaming pass.
Note
This function relies on the internal implementation of VariableRenaming to correctly identify all definition and use sites.

bool SDG::isParaPassedByRef ( SgType * type)

Check if a parameter of the given type in a function call is passed by reference or not.

Determines if a given type is passed by reference, pointer, or as an array.

This function checks the underlying type properties to identify if the parameter is passed using reference semantics. It first strips any typedef wrappers from the provided type using the SgType::STRIP_TYPEDEF_TYPE flag to ensure the underlying base type is evaluated. It then evaluates whether the resulting type is a pointer, a reference, or an array type.

Parameters
typeA pointer to the SgType representing the parameter type to be checked.
Returns
True if the type is a pointer, a reference, or an array; false otherwise.
Precondition
type must not be a null pointer.
Postcondition
The input pointer type may be modified internally via the stripType method, though the pointer itself remains valid.
Note
This function relies on SageInterface utility functions for type inspection.
