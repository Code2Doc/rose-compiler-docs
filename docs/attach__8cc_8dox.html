Attaches a MetricAttr to an SgType node, accumulating values if the attribute already exists.

This function attempts to attach a MetricAttr to a specified SgType node under a given attribute name. If an attribute with the same name already exists on the node, the function retrieves the existing MetricAttr, adds its value to the value of the provided attr, and updates the node with the new value. If the attribute does not exist, it is simply attached to the node. If the verbose flag is set to true, a notification is triggered via notifyAttached.

Parameters
nodeA pointer to the SgType node to which the attribute will be attached.
attr_nameThe string identifier for the attribute being attached or updated.
attrA pointer to the MetricAttr object containing the value to be attached or added.
verboseA boolean flag indicating whether to trigger a notification after attachment. Defaults to false.
Returns
True if the attribute was successfully attached or updated; false if the provided node is NULL.
Precondition
node must not be NULL for a successful attachment.
If the attribute name already exists, the existing attribute must be castable to MetricAttr.
Postcondition
If the attribute existed, its value is incremented by the value of the provided attr, and the node is updated.
If the attribute did not exist, the node now contains the provided attr under attr_name.
Note
This function uses dynamic_cast to ensure the existing attribute is of type MetricAttr.
The function relies on ROSE_ASSERT to validate the type of the existing attribute.

Determines if the line ranges of a ROSE SgNode and a profile location overlap.

This function checks for an intersection between the source code location represented by an SgLocatedNode and a location provided by profiling data (RoseHPCT::Located). The comparison involves verifying that both nodes refer to the same file (using suffix matching for filename comparison) and checking if their respective line ranges (start to end) overlap.

The implementation includes logic to handle SgFunctionDefinition nodes by redirecting the check to the underlying function declaration to ensure the line ranges reflect the declaration rather than the function body start. It also contains heuristics to adjust for potential inaccuracies in line number reporting in ROSE (e.g., for loop statements) and handles cases where HPCToolkit might provide invalid line ranges.

Parameters
nodeA pointer to the SgLocatedNode representing the source code element to check.
plnodeA pointer to the RoseHPCT::Located object containing the profile line range and file information.
Returns
True if the line ranges of the two nodes overlap and they belong to the same file; false otherwise. Returns false if the node is NULL.
Precondition
plnode must not be NULL.
Postcondition
The function does not modify the state of the input nodes.
Note
The function uses a suffix-based approach for filename comparison to account for potential differences in absolute vs. relative paths.
The function contains logic to handle cases where the end line is less than the start line by normalizing them, specifically to address known issues in ROSE/EDG line number reporting.

This function iterates through a collection of attached nodes, where each entry maps a profile IR node to a set of matched AST nodes. For each IR node, the function calculates the distribution of its corresponding AST nodes across different tree depths. It then identifies all metrics attached to the profile IR node and scales their values by dividing the original value by the number of AST nodes present at that specific depth. This ensures that metrics are averaged appropriately when multiple AST nodes share the same depth level.

Precondition
