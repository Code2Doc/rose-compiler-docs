4// DQ (5/4/2011): This is the redesign of the support for name qualification.
5// The steps are:
6// 1) All using directives put alias sysmbols into place into the scope
7// where they appear and for each symbol in the scope being used.
8// 1) Compute the hidden type tables
9// 2) Use the hidden type tables to determine which types need qualification.
10
11// * We will want to keep track of hidden variables too! But first handle types.
12// * When we refer to names it will be of either variables or types.
13
14// This is a part of a rewrite of the name qualification support in ROSE with the follwoing properties:
15// 1) It is exact (no over qualification).
16// 2) It handled visibility of names constructs
17// 3) It resolves ambiguity of named constructs.
18// 4) It resolves where type elaboration is required.
19// 5) The inputs are carried in the SgUnparse_Info object for uniform handling.
20// 6) The the values in the SgUnparse_Info object are copied from the AST references to the named
21// constructs to avoid where named constructs are referenced from multiple locations and the
22// name qulification might be different.
23//
24// 7) What about base class qualification? I might have forgotten this one! No this is handled using standard rules (above).
