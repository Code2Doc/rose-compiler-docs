void markTemplateInstantiationsForOutput ( SgNode * node)

Marks template instantiations for output within the code generation process.

Fixups template instantiations generated by ROSE from template declarations.

Marks template instantiations for output during the code generation process.

This function identifies and marks template instantiations (member functions, functions, and classes) that need to be included during the unparsing/code generation phase. By isolating the control over template instantiation output, the design of the unparser is simplified. The function handles various scenarios including template specializations and cases where the template definition is present in the source file. It specifically addresses differences in how various compilers (like G++) handle template definitions and member function scopes.

The implementation follows a multi-phase approach:

  1. Locates all template instantiations referenced in the source file.
  2. Processes member function template instantiations:
    • Marks specializations for output.
    • If the definition is in the source file, marks it for output if defined within the class.
    • Handles prototype construction and definition movement for specific G++ versions.
  3. Processes function template instantiations:
    • Marks specializations for output.
    • Avoids marking if the definition is already in the source file.
  4. Processes class template instantiations:
    • Marks specializations for output.
    • Avoids marking if the definition is already in the source file.
    • Ensures member function declarations are inserted correctly after class template instantiations.

The function also supports recursive processing when an SgProject node is encountered by iterating through all files within the project.

Parameters
nodeA pointer to the SgNode to be processed. This can be an SgSourceFile, an SgProject, or other node types.
Precondition
node must not be NULL.
Postcondition
The template instantiations within the scope of the provided node (or its associated files/project) are marked for output in the AST.
Note
This function relies on the availability of the full AST (including SgFile) to perform necessary fixups.
Performance tracking is integrated via a TimingPerformance object.

This function identifies and flags template instantiations (member functions, function templates, and class templates) that need to be included in the unparser output. By isolating the control over template instantiation output, the design of the unparser is simplified. The function handles various scenarios including template specializations and cases where the template definition is present within the source file.

The implementation follows a multi-phase approach:

  1. Locates all template instantiations referenced in the source file.
  2. Processes member function template instantiations: a) Marks specializations for output. b) If the associated template definition is in the source file, marks it for output if defined in the class, or handles prototype insertion/definition movement depending on the compiler version (e.g., G++ 3.3.x vs 3.4.x/4.x).
  3. Processes function template instantiations: a) Marks specializations for output. b) Does not mark for output if the associated template definition is in the source file.
  4. Processes class template instantiations: a) Marks specializations for output. b) Does not mark for output if the associated template definition is in the source file. c) Ensures member function/friend function declarations are inserted after the class template instantiation if the class itself is not marked for output.

If the provided node is an SgProject, the function recursively calls itself for every file within that project.

Parameters
nodeA pointer to the SgNode to be processed. This can be an SgSourceFile, an SgProject, or other AST nodes.
Precondition
node must not be NULL.
Postcondition
The state of the AST nodes within the scope of the provided node is updated to indicate which template instantiations should be included in the output.
Note
This function relies on the availability of the full AST (including SgFile) to perform the necessary fixups.
