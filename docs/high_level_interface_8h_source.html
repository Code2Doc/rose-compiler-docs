6/* *********** Notes on the construction of IR nodes in ROSE from scratch **********
7
8 Building IR nodes in ROSE is a matter of following a few rules, most IR nodes
9are easy to build, but a few are more complex. This High Level Intefce defines simple
10functions to call to simplify how an AST can be built up from scratch.
11General rules are:
12 1) Use the new IR nodes constructors that do NOT take a Sg_File_Info pointer.
13 E.g. SgForStatement (SgStatement *test, SgExpression *increment, SgBasicBlock *loop_body)
14
15 2) Always set the scope if the scope is explicitly defined in that IR node
16 (call SgStatement::hasExplicitScope() to test for this).
17
18 3) The parent of the IR nodes should be set if it is a SgLocatedNode or a for a few case of a SgSupport IR node:
19 (SgInitializedName, SgFile, SgDirectory, Sg_File_Info, SgModifier, SgSymbolTable, SgTemplateArgument, SgTemplateArgumentList,
20 SgFunctionParameterTypeList, SgBaseClass, SgTemplateParameter, SgTemplateParameterList, SgTypedefSeq, (and maybe a few others)).
21
22 4) Set the source code poisition, call SgLocatedNode::set_startOfConstruct() with a valid
23 Sg_File_Info object. Also, call SgLocatedNode::set_endOfConstruct() with a valid
24 Sg_File_Info object. Note that all Sg_File_Info object must be unique (can not be shared).
25
26 5) For SgExpression objects, if the expression is an operator, then the position location of
27 the operator need be set. The operator position is optional, so need not be set for
28 transformations (I think).
29
30 6) Declarations which generate symbols need to be added to symbol tables (use member function
31 hasAssociatedSymbol() to check if a symbol is defined for a declaration).
32
33For source location position information, if an AST is being constructed from scratch, then it
34does not correspond to a position in the source code and the Sg_File_Info object should be
35generated by a static member function Sg_File_Info::generateDefaultFileInfoForTransformationNode().
36
37 */
