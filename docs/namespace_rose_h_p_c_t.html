Attach metrics from a ProfIR tree to a Sage IR tree.

Attaches performance metrics from a profile IR tree to a Sage project AST.

This function performs a multi-stage traversal of the Sage AST to map profiling information from an HPC IR tree onto the corresponding source code nodes. It utilizes a MetricAttachTraversal to traverse the sage_root in preorder, matching nodes from the hpc_root. If enable_debug is active, it performs source code annotation. After the initial attachment, the function normalizes shared metrics across AST nodes to ensure accurate distribution and then executes a MetricFixupTraversal to finalize the metric values across the project structure.

Parameters
hpc_rootA pointer to the root of the profile IR tree containing the collected performance metrics.
sage_rootA pointer to the SgProject representing the AST to which metrics will be attached.
verboseA boolean flag indicating whether to enable verbose logging during the attachment and fixup processes.
Precondition
hpc_root must be a valid, non-null pointer to an IRTree_t.
sage_root must be a valid, non-null pointer to an SgProject.
Postcondition
The metrics from hpc_root are integrated into the nodes of sage_root.
The metrics in sage_root are normalized and fixed up to ensure consistency.
Note
The function relies on the global enable_debug variable to determine whether to perform source code annotation.
The implementation uses a preorder traversal strategy for both the attachment and the fixup phases.

EquivPathMap_t RoseHPCT::getEquivPaths ( vector< string > & argvList)

Retrieves and parses path equivalence mappings from command line arguments.

This function extracts path equivalence definitions from a list of command line arguments. It searches for the specific option defined by OPTION_HPCTEQPATH. Each entry found is parsed to establish a mapping between a source path and a target path. The parsing logic looks for an '=' delimiter; if found, the string is split into two parts. If no '=' is present, the entire string is treated as the source path, and the target path defaults to ".".

Parameters
argvListA reference to a vector of strings containing the command line arguments.
Returns
An EquivPathMap_t object containing the parsed key-value pairs representing the established path equivalences.
Precondition
The argvList must contain valid command line arguments, potentially including the OPTION_HPCTEQPATH flag.
Postcondition
Returns a map where each key is a source path and each value is the corresponding destination path.
Note
The function prints the established path equivalences to the standard error stream (cerr) during the parsing process.

◆ loadGprofVec()

ProgramTreeList_t RoseHPCT::loadGprofVec ( const std::vector< gprof_info > & vec)

Converts gprof line-by-line profiling information into a tree-like Profile IR.

This function iterates through a vector of gprof_info objects to reconstruct a hierarchical representation of program execution profiles. It builds a tree structure consisting of a Program root, File nodes, Procedure nodes, and Statement nodes. The implementation uses static maps to maintain persistence of file and function nodes across calls, allowing for the incremental construction of the IR tree. For each entry in the input vector, the function identifies or creates the appropriate file and procedure nodes and attaches metrics such as wall clock time (self-seconds) and execution percentage.

Parameters
vecA constant reference to a vector of gprof_info objects containing the profiling data to be processed.
Returns
A ProgramTreeList_t containing the root of the constructed Profile IR tree. If the input vector is empty, an empty list is returned.
Precondition
The input vector vec should contain valid gprof_info objects with accessible file names, function names, and line numbers.
Postcondition
The returned ProgramTreeList_t contains a tree structure where the root represents the program, and children represent files, procedures, and statements.
Note
This function uses static variables (prog_root, file_node_map, and func_node_map) to persist the tree structure and node mappings. Consequently, subsequent calls to this function will append to the existing tree rather than starting from scratch.
The function assumes that the end line of a procedure is equal to its beginning line when creating new Procedure nodes.
Metrics are attached as follows: self-seconds are treated as wall clock time, and the time percentage is converted from a percentage value to a decimal by dividing by 100.0.

reading gprof information into generic Container

Reads profiling information from a gprof file into a provided container.

This function reads a file line by line and populates the Container c with the gprof information found. Consider resizing the Container to an appropriate size, for performance reasons.

Parameters
gprof_filePath to gprof output file
cContainer to hold the data (must provide a push_back( const gprof_info& info ) member function )

This function opens a file specified by the gprof_file path and iterates through it line by line. For each line, it attempts to instantiate a gprof_info object. If the construction is successful, the resulting object is appended to the provided container. The function uses a try-catch block to silently ignore lines that fail to parse or cause exceptions during the creation of the gprof_info object, ensuring that the process continues for the remainder of the file.

Parameters
gprof_fileA pointer to a null-terminated character string representing the path to the gprof output file.
cA reference to a container (e.g., std::vector, std::list) that supports the push_back method. This container will be populated with successfully parsed gprof_info objects.
Precondition
The container c must be initialized and must implement a push_back member function.
Postcondition
The container c will contain all valid gprof_info objects parsed from the file.
Note
The function suppresses all exceptions thrown during the parsing of individual lines. This means that if a line is malformed, it will be skipped without notifying the caller.
