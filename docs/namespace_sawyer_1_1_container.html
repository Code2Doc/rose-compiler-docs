Detailed Description

Auto-generated documentation for the Sawyer::Container namespace.

Container classes that store user-defined values.

This library implements a number of container classes. In general, these classes adhere to the naming scheme used throughout the library, which might be somewhat surprising compared with STL containers. The major differences are:

  • All type names are CamelCase with an initial capital letter, such as Iterator, ConstIterator, etc.
  • Some containers have multiple categories of iterator, such as iterators that visit the storage nodes of the container, and iterators that visit the values logically contained in the container. For instance one can iterate over the keys alone in a key/value map, or the values alone, or the combined storage nodes that have a key/value pair.
  • The containers have no direct begin and end methods, but rather return iterator ranges with methods like, for the key/value map container, keys, values, and nodes. This allows containers return different types of iterators. The iterator ranges have the usual begin and end methods.
  • Most predicates start with the word "is", such as isEmpty so they cannot be confused with a similar verb (i.e., it is quite obvious that isEmpty does not empty the container).
  • The insert methods come in different flavors depending on what's being inserted. Inserters that insert a value are named insert; those that insert multiple values, like from another container or iterator range, are named insertMultiple. This gives the API more flexibility and consistency across different containers.
  • The erase methods also come in different flavors: erase is to erase a single specified value, eraseAt is for erasing based on location (i.e., iterators that point into that container), and eraseMultiple is to erase multiple values at once (e.g., values obtained from a different container). As with insert, this gives container designers more flexibility and at the same time improves consistency.

Overloads the stream insertion operator for the Trace class.

This function provides a way to output the contents of a Trace object directly to an output stream. It delegates the actual formatting and printing logic to the Trace::print method.

Parameters
outThe output stream where the trace information will be written.
traceThe Trace object instance to be streamed.
Returns
A reference to the provided output stream (out) to allow for chained stream operations.
Precondition
The Trace object must be in a valid state such that its print method can be executed.
Postcondition
The content of the trace is written to the stream, and the stream remains in a valid state.
Note
This operator is useful for logging or debugging Trace objects using standard C++ I/O streams.
