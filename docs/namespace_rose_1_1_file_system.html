Copies the contents of a source file to a destination file.

Copy a file.

Copies the contents of the source file to the destination file, overwriting the destination file if it existed.

This function performs a binary copy of a file from the source path to the destination path. Instead of using boost::filesystem::copy_file, which may cause linking issues between C++11 and C++89 Boost versions in certain environments (referencing Boost issue #6124), this implementation utilizes C++ stream I/O. The implementation uses path::string rather than path::native to ensure compatibility with Filesystem version 2.

Parameters
srcThe path to the source file to be copied.
dstThe path to the destination file where the content will be written.
Warning
This function throws a boost::filesystem::filesystem_error if the reading from the source file fails or if writing to the destination file fails.
Precondition
The source file must exist and be readable.
Postcondition
If the function completes successfully, the destination file will contain an exact binary copy of the source file. If the destination file already existed, its previous contents are overwritten.
Note
The use of std::ifstream and std::ofstream with std::ios::binary ensures that the file is treated as a binary stream, preventing unintended newline translations on non-POSIX systems.

const Path & root,
const Path & destinationDirectory )

Copies a collection of files from a source root to a destination directory while preserving directory structure.

Copy files from one directory to another.

Each of the specified files are copied from their location under root to a similar location under destinationDirectory. Subdirectories of the destination directory are created as necessary.

Any file whose name is outside the root directory will similarly be created outside the destinationDirectory. For instance, copyFiles(["bar/baz"], "foo", "frob") will copy "bar/baz" to "frob/../bar/baz" since "bar" is apparently a sibling of "foo", and therefore must be a sibling of "frob".

Throws a boost::filesystem::filesystem_error on failure.

This function iterates through a list of file paths, calculates their relative paths with respect to a provided root directory, and recreates the corresponding directory hierarchy within a destination directory. For each file in the input vector, the function determines the target directory by applying the relative path transformation, ensures the target directory exists using boost::filesystem::create_directories, and then performs the actual file copy operation.

Parameters
fileNamesA vector of Path objects representing the source files to be copied.
rootThe base directory path used as the reference point for calculating relative paths.
dstDirThe destination directory where the files and their reconstructed subdirectories will be placed.
Precondition
The paths provided in fileNames, root, and dstDir must be valid and accessible.
Postcondition
The files specified in fileNames will exist in the dstDir, maintaining the same relative structure as they had under the root directory. The directories required for the destination paths will have been created.
Note
This function relies on the existence of makeRelative, copyFile, and the boost::filesystem library.
Warning
If the destination directory or its parent directories cannot be created due to permission issues, the function may throw an exception from the underlying filesystem library.

Searches for paths within a directory that satisfy a given selection criteria.

Entries within a directory.

Returns a list of entries in a directory–the contents of a directory–without recursing into subdirectories. The return value is a sorted list of paths, each of which contains root as a prefix. If a select predicate is supplied then only paths for which the predicate returns true become part of the return value. The predicate is called with the path that would become part of the return value. The root itself is never returned and never tested by the predicate.

If select is not specified then all entries are returned.

This function iterates through the contents of the specified directory root. For each entry found within the directory, it applies the provided select predicate function. If the predicate returns true for a path, that path is added to the resulting collection. The final list of matching paths is returned in lexicographically sorted order.

Parameters
rootThe starting directory path to begin the search.
selectA callable object (predicate) that accepts a Path and returns a boolean value indicating whether the path meets the criteria.
Returns
A sorted vector of Path objects that matched the selection criteria.
Precondition
The root path must exist and be a valid directory for the DirectoryIterator to function correctly.
Postcondition
The returned vector is sorted in ascending order based on the Path comparison operator.
Note
The function uses a DirectoryIterator to traverse the filesystem. The complexity of the function is O(N log N) where N is the number of matching paths, due to the sorting step.

Recursively traverses a directory structure to find paths matching a specific predicate.

Recursive list of names satisfying predicate.

Returns a list of entries in a directory and all subdirectories recursively. The return value is a sorted list of paths, each of which contains root as a prefix. If a select predicate is supplied then only paths for which the predicate returns true become part of the return value. If a descend predicate is supplied then this algorithm only recurses into subdirectories for which descend returns true. The predicates are called with the path that would become part of the return value. The root itself is never returned and never tested by the select or descend predicates.

If select is not specified then all entries are returned. If descend is not specified then the algorithm traverses into all subdirectories. Symbolic links to directories are never followed, but are returned if the select predicate allows them.

This function performs a depth-first traversal of the directory tree starting from the provided root path. It utilizes a RecursiveDirectoryIterator to iterate through all files and subdirectories. For each entry encountered, the function applies a selection predicate to determine if the path should be added to the results and a descent predicate to determine whether the traversal should continue into the current directory's subdirectories. After the traversal is complete, the resulting list of paths is sorted lexicographically.

Parameters
rootThe starting directory path from which the recursive search begins.
selectA callable object (predicate) that accepts a Path and returns a boolean. If it returns true, the current path is added to the collection of matching paths.
descendA callable object (predicate) that accepts a Path and returns a boolean. If it returns false, the iterator is instructed to skip the recursion into the current directory's children.
Returns
A sorted vector of Path objects that satisfied the selection predicate.
Precondition
The root path must exist and be accessible by the current process.
Postcondition
The returned vector contains all paths that matched the select predicate, sorted in ascending order.
Note
The complexity of the function depends on the number of files in the directory tree and the efficiency of the provided select and descend predicates.

◆ makeNormal()

Path Rose::FileSystem::makeNormal ( const Path & )

Normalizes a given path by resolving relative components like "." and "..".

Normalize a path name.

Normalizes a path by removing "." and ".." components to the extent which is possible.

For instance, a name like "/foo/bar/../baz" will become "/foo/baz" and the name "/foo/./baz" will become "/foo/baz". However, the names "/../foo" and "./foo" cannot be changed because removing the ".." in the first case would place it in a different directory if the name were appended to another name, and in the second case it would convert a relative name to an absolute name.

This function processes the input path component by component to create a canonical-like representation. It iterates through the path elements, skipping current directory indicators (".") and handling parent directory indicators ("..") by removing the preceding component from the accumulated path stack, provided the stack is not empty. Finally, it reconstructs a new Path object from the processed components.

Parameters
pathThe input path to be normalized.
Returns
A new Path object representing the normalized version of the input path.
Precondition
The input path should be a valid Path object.
Postcondition
The returned path will not contain "." components and will have ".." components resolved against preceding elements.
Note
This implementation uses an iterative approach with a vector to manage path components during the normalization process.
