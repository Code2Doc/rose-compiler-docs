void Outliner::collectVars ( const SgStatement * s,
ASTtools::VarSymSet_t & syms )

Computes the set of variables in 's' that need to be passed to the outlined routine (semantically equivalent to shared variables in OpenMP).

Identifies the set of variables that must be passed as parameters to an outlined function.

Collect the variables to be passed if 's' is to be outlined.

Note: user codes should handle non-generic variable handling on their own. Outliner only handles generic operations. For example, in OpenMP translation calling outliner: OpenMP specific variables such as private, firstprivate, reduction variables are handled by OmpSupport::transOmpVariables() before it calls outliner. So the outliner can focus on generic operations while the caller should handle their special variables in advance.

This function determines which variable symbols used within a specific statement s need to be included in the parameter list of a newly created outlined function. The logic distinguishes between variables defined locally within the statement and those referenced from outer scopes.

The implementation follows these steps:

  1. Identifies the enclosing function definition for the statement s.
  2. Computes the set U (all variables referenced within s) and the set L (variables defined within s).
  3. Calculates the difference U - L, representing variables used in s but not declared within it.
  4. If Outliner::useNewFile is true, it adopts a "lazy" approach by including all variables in U - L.
  5. If Outliner::useNewFile is false, it calculates the intersection of U - L with the set Q (variables visible at s within the enclosing function), ensuring only necessary local-scope variables are passed.
Parameters
sA pointer to the SgStatement being analyzed for variable usage.
symsA reference to a VarSymSet_t where the resulting set of required variable symbols will be stored.
Precondition
The pointer s must be valid and must be contained within a valid SgFunctionDefinition.
Postcondition
The syms set will be populated with the identified variable symbols required for the outlined function.
Note
The function uses ROSE_ASSERT to ensure the existence of an outer function definition.
The behavior of the variable selection depends on the global state of Outliner::useNewFile.

Result Outliner::outlineBlock ( SgBasicBlock * s,
const string & func_name_str )

Extracts a basic block and transforms it into a separate function call.

This function performs a complex code refactoring transformation known as "outlining." It takes a specified basic block, extracts its logic, generates a new function definition (either in the current scope or a new source file), and replaces the original block with a call to this newly created function. The process involves analyzing variable usage, handling parameter passing (including structure wrappers or pointer dereferencing), managing preprocessing information, and ensuring that all necessary dependencies and symbols are correctly propagated to the new function scope.

The implementation follows several steps:

  1. Preparation: Determines if a new file is needed, captures preprocessing information, and identifies variables that need to be passed as parameters.
  2. Analysis: Performs liveness analysis and identifies read-only or pointer-dereferencing variables to optimize the parameter list.
  3. Generation: Creates the function declaration, potentially generating a structure wrapper for parameters, and generates the function body.
  4. Insertion: Inserts the new function into the global scope and handles the replacement of the original block with a function call statement.
  5. Cleanup and Fixup: Restores preprocessing information, fixes variable references, and handles dependent declarations if a new file was created.
Parameters
sA pointer to the SgBasicBlock that is to be outlined.
func_name_strA string representing the name to be assigned to the newly generated function.
Returns
An Outliner::Result object containing the newly created function declaration, the replacement function call statement, the potentially new source file, and the deferred transformation information for header files.
Precondition
The pointer s must be a valid, non-null SgBasicBlock.
Postcondition
The original block s is replaced by a function call in the AST, and the logic of s is moved to a new function declaration.
Note
The function handles various configuration flags such as Outliner::useNewFile, Outliner::useStructureWrapper, and Outliner::use_dlopen to determine the specific transformation strategy used.
If use_dlopen is enabled, the function handles the generation of shared library loading logic (e.g., using dlopen and dlsym patterns).
