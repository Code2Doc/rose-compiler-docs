boundaries nlohmann::detail::dtoa__impl::compute_boundaries ( FloatType value)

Computes the floating-point rounding boundaries for a given value.

This function calculates the interval [w_minus, w_plus] such that any real number strictly within this range rounds to the input value. The implementation decomposes the IEEE-754 floating-point representation into a custom DIY floating-point format (diyfp) to perform exact arithmetic on the significand and exponent. It identifies the predecessor (v-) and successor (v+) of the input value and then computes the midpoints (m- and m+) between the value and its neighbors to define the boundaries.

Parameters
valueThe floating-point value for which the boundaries are to be computed. Must be a finite, positive number.
Returns
A struct of type boundaries containing the normalized input value, the lower boundary (w_minus), and the upper boundary (w_plus).
Precondition
value must be a finite number (std::isfinite(value) must be true).
value must be greater than 0.
The FloatType must follow the IEEE-754 (IEC 554) floating-point standard.
Postcondition
The returned boundaries define a range where all real numbers strictly between the boundaries round to the input value.
Note
The function uses a static_assert to ensure that the provided FloatType is compatible with the expected IEEE-754 bit manipulation logic.
The precision and bias are derived from std::numeric_limits<FloatType>.

Retrieves a precomputed power of ten from a lookup table based on a binary exponent.

This function provides an efficient way to find a cached power of ten such that the resulting decimal exponent covers the range of the product of a normalized dyadic floating-point number and a power of two. It avoids expensive floating-point operations by using a fixed-point approximation of log10(2) (specifically 78913 / 2^18).

The implementation uses a lookup table kCachedPowers to map the calculated decimal exponent k to a cached_power entry. The table is designed such that the difference between adjacent decimal exponents is at most 8, ensuring the product's exponent remains within the bounds of the table entries.

Parameters
eThe binary exponent of the operand for which the cached power is being calculated.
Returns
A cached_power structure containing the precomputed mantissa, binary exponent, and decimal exponent suitable for the given input e.
Precondition
The input parameter e must be within the range [-1500, 1500].
Postcondition
The returned cached_power satisfies the condition that the product's exponent lies within the range [alpha, gamma] defined by the table entry.
Note
The approximation used for log10(2) is sufficient for the required precision in the range of IEEE double precision exponents.
The function relies on kAlpha being defined in the surrounding scope.

Implements the Grisu2 algorithm for fast floating-point to decimal string conversion.

This function performs a high-speed conversion of a floating-point value within a specified interval [m_minus, m_plus] to its shortest decimal representation. The algorithm works by scaling the input values (v, m_minus, and m_plus) by a cached power of ten to bring the exponent into a manageable range [alpha, gamma]. It then calculates an expanded interval [M_minus, M_plus] to account for rounding errors introduced during the scaling process, ensuring that any value in the expanded range correctly rounds to the scaled value w. Finally, it delegates the digit generation to the grisu2_digit_gen function.

Parameters

decimal_exponentA reference to an integer that will store the calculated decimal exponent.

m_plusThe upper bound of the input interval.
Precondition
The exponents of m_plus, m_minus, and v must be equal (m_plus.e == m_minus.e and m_plus.e == v.e).
Postcondition
The buffer buf contains the decimal representation of the value, and len and decimal_exponent are updated with the resulting string length and exponent respectively.
Note
The algorithm uses a cached power of ten to optimize the scaling process.
The expansion of the interval to [M_minus, M_plus] is a technique to ensure robustness against rounding inaccuracies in the multiplication step.

This function implements the Grisu2 algorithm to generate the shortest possible decimal representation of a floating-point number that rounds back to the target value w. The algorithm works by generating digits from left to right, first processing the integral part of the significand and then the fractional part, while ensuring the resulting value remains within the interval [M_minus, M_plus]. It utilizes a splitting technique where the upper bound M_plus is decomposed into a part aligned with the power-of-two boundary and a remainder to facilitate digit extraction.
