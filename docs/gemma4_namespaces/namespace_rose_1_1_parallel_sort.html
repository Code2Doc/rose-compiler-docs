Performs a multi-threaded quicksort on a range of elements.

Sort values in parallel. Sorts the values between begin (inclusive) and end (exclusive) according to the comparator compare using nthreads threads. Multi-threading is only used if the size of the range of values exceeds a certain threshold.

Note: using normal C++ iterators with debugging support will result in slower execution the more threads are used because the iterator dereference operators serialize some sanity checks which causes lock contention. It is best to do the sanity check once up front, then then call the sort function with pointers. For example:

std::vector<Thing> data;
// This method might get slower as nthreads increases
quicksort(data.begin(), data.end(), thingComparer, nthreads);
// But this should scale well provided data.size() is large enough.
quicksort(&data[0], &data[0]+data.size(), thingComparer, nthreads);

Performs a multi-threaded quicksort on a range of elements.
Definition ParallelSort.h:141

This function implements a parallel version of the quicksort algorithm using a task-based approach. It utilizes a job system to distribute sorting tasks across multiple worker threads. The implementation creates a specified number of worker threads and uses a shared job object to manage the partitioning and sorting of the range defined by [begin, end). The calling thread also participates in the computation as a worker.

Parameters
beginAn iterator pointing to the first element of the range to be sorted.
endAn iterator pointing to the element following the last element of the range.
nThreadsThe total number of threads to be used for the sorting process, including the calling thread.
compareA binary predicate that takes two elements and returns true if the first element is less than the second.
Precondition
The range [begin, end) must be valid and accessible via RandomAccessIterator.
The compare function must satisfy the requirements of a strict weak ordering.
nThreads should be at least 1.
Postcondition
The elements in the range [begin, end) are sorted according to the provided compare predicate.
All spawned worker threads are joined before the function returns.
Note
This implementation uses boost::thread for concurrency management.
The function allocates an array of boost::thread objects on the heap; ensure the environment supports this allocation.
Warning
The function uses 'new' to allocate the worker thread array, which relies on the successful execution of the loop and join logic to prevent leaks in the context of this specific implementation.
If nThreads is 0, the implementation internally adjusts the worker count to ensure at least one thread (the caller) participates.
