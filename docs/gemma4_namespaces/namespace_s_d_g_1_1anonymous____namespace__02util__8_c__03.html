Recursively appends a vertex and all its reachable successors to a list of vertices.

This function performs a depth-first traversal of the Control Flow Graph (CFG) starting from a given vertex. It traverses the graph using the provided adjacency map (iSucc) and collects every reachable vertex into the provided vertices vector. The implementation uses recursion to visit each successor found in the adjacency set of the current vertex.

Parameters
vThe starting vertex from which the traversal begins.
verticesA reference to a vector of vertices that will be populated with the visited vertices.
iSuccA constant reference to a map representing the CFG, where each key is a vertex and the associated value is a set of its immediate successor vertices.
Precondition
The vertex v should be a valid vertex within the context of the graph represented by iSucc.
If v is found in iSucc, the associated set of successors must not be empty (enforced by ROSE_ASSERT).
Postcondition
The vertices vector will contain the vertex v and all vertices reachable from v via the successors defined in iSucc.
Note
This function uses recursion; for extremely deep or complex control flow graphs, there is a potential risk of stack overflow.
The function assumes that the graph represented by iSucc is a Directed Acyclic Graph (DAG) or that the traversal does not encounter cycles that would lead to infinite recursion.

bool SDG::anonymous__namespace_02util_8C_03::checkCycle ( const ControlFlowGraph & cfg)

Checks if the provided Control Flow Graph contains any cycles.

This function determines the presence of cycles within a Control Flow Graph (CFG) by utilizing the concept of Strongly Connected Components (SCCs). The algorithm works by creating a copy of the input CFG and adding a synthetic edge from the exit node back to the entry node. After this modification, the function calculates the number of strongly connected components using the Boost Graph Library's strong_components algorithm. If the resulting number of components is exactly 1, it implies that all nodes are part of a single interconnected structure (including the newly added loop-back edge), indicating the absence of any cycles that would otherwise prevent reaching the exit.

Parameters
cfgA constant reference to the ControlFlowGraph to be analyzed.
Returns
True if the graph contains no cycles (i.e., the graph is a single strongly connected component after adding the exit-to-entry edge), false otherwise.
Precondition
The provided ControlFlowGraph cfg must be a valid, well-formed graph structure with defined entry and exit nodes.
Postcondition
The original ControlFlowGraph cfg remains unmodified as the algorithm operates on a local copy.
Note
This implementation relies on the Boost Graph Library (BGL) for computing strongly connected components.
