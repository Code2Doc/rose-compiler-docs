Calculates the dominance frontiers, immediate dominators, and immediate post-dominators for a given function.

This function constructs a Control Flow Graph (CFG) from the provided function definition and computes the dominance frontiers for all nodes. The implementation utilizes the algorithm described by Cytron et. al (1991) to determine the dominance frontiers. During the process, the function builds a dominator tree using a Boost adjacency list representation and performs a reverse topological sort to propagate dominance frontier information. Additionally, if provided, the function populates maps containing the immediate dominator and immediate post-dominator for each node in the CFG.

Parameters
funcA pointer to the SgFunctionDefinition representing the function for which the CFG and dominance frontiers are to be computed.
iDominatorMapA pointer to a map where the immediate dominator of each CFG node will be stored. If NULL, no dominator map is updated.
iPostDominatorMapA pointer to a map where the immediate post-dominator of each CFG node will be stored. If NULL, no post-dominator map is updated.
Returns
A map where each key is a CFG node and the value is a set of CFG nodes that belong to that node's dominance frontier.
Precondition
func must not be NULL and must contain a valid function definition from which a CFG can be constructed.
If iDominatorMap is not NULL, it must be an initialized map and should not already contain entries for the nodes being processed.
If iPostDominatorMap is not NULL, it must be an initialized map and should not already contain entries for the nodes being processed.
Postcondition
The returned map contains the calculated dominance frontiers for all nodes in the function's CFG.
If iDominatorMap is not NULL, it is updated with the immediate dominator for each node in the CFG.
If iPostDominatorMap is not NULL, it is updated with the immediate post-dominator for each node in the CFG.
Note
The implementation relies on the Boost Graph Library for graph structures and topological sorting.
The algorithm uses include and define logic internally via the CFG and Boost components.
The function uses ROSE_ASSERT to validate the integrity of the dominator tree and vertex mappings.

Computes the iterated dominance frontier starting from a given set of nodes.

This function performs a graph traversal (specifically a depth-first search approach using a worklist) to find the union of all dominance frontiers reachable from the provided start nodes. It iteratively explores the dominance frontier of each node encountered, effectively calculating the transitive closure of the dominance frontier relationship starting from the initial set.

Parameters
dominanceFrontiersA map where each key is a control flow graph node and the value is a set of nodes representing that node's dominance frontier.
startNodesA vector of initial nodes from which the iterated frontier calculation begins.
Returns
A set containing all nodes that belong to the iterated dominance frontier reachable from the startNodes.
Precondition
The dominanceFrontiers map must contain an entry for every node encountered during the traversal. If a node is present in a frontier but not as a key in the map, a ROSE_ASSERT failure will occur.
Postcondition
The returned set contains all nodes reachable through the dominance frontier relation from the input startNodes.
Note
The implementation uses a worklist-based approach to ensure all reachable nodes in the dominance frontier graph are visited exactly once.
